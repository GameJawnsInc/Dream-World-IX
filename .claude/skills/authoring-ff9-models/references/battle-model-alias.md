# Battle-model alias chain (`resolve_prefab`)

Distilled from memory `project-ff9-battle-model-export-gap` (★ FIXED 2026-07-10). Quoted lines are
verbatim from that file; read it for the full verification record.

## The mechanism (engine-verified, mirrored by the kit)

- "**Battle loads the SAME prefab as field.** `GEO_MAIN_B0_000` → `CheckUpscale` →
  `GEO_MAIN_UP0_ZDN` → `GetRenameModelPath`/`revertUpscaleTable` → `GEO_MAIN_F0_ZDN` = prefab
  **98**." The battle BODY is the field body (`mesh0/1`); "`battle_model0/1` is a **103-vert
  battle-only OVERLAY** (Zidane's twin Orichalcum daggers)".
- "**Mesh and clips come from DIFFERENT ids**: geometry from the prefab (98), clips from
  `animations/{requested_id}/`" — identity stays the REQUESTED id, geometry follows the DONOR prefab.
- "**Vivi (B0_006) is the genuine own-prefab case** (chain loops back to its own 5415)" — why Vivi
  edits worked pre-fix and the gap "looked completed".

## The kit mirror (zero DLL)

- "**`extract.resolve_prefab(token) -> (prefab_name, prefab_id, prefab_tint)`** replays
  CheckUpscale→GetRenameModelPath", backed by the baked alias tables in `_modelalias.py`
  (regenerated by `_regen_modelalias.py` from Memoria's `ModelFactory.cs`).
- "**`resolve_geo` UNTOUCHED** (identity/animations = requested id; 6 callers depend on it)."
- Coverage: **71 alias ids** export/preview/reskin/deploy engine-faithfully; "**The 43 unshipped ids
  refuse actionably** (\"UNSHIPPED model: no geometry on disc … no donor in the alias tables\")
  instead of the fake `models/2/5414/5414.fbx` path."
- Type dir comes from the POST-alias name: "Type dir = the POST-UPSCALE name's group
  (`GEO_MAIN_B0_015` → `models/5/`)"; textures read from the PREFAB's folder.

## Deploy traps

- "**Deploys land at the DONOR prefab folder** (`export.deploy_target`) — the only path
  `SearchAssetOnDisc` probes (post-alias)." An override written at the requested id's own folder is
  dead.
- "**Overlay meshes are STRIPPED from overrides** (`strip_overlay_meshes` …): the loose importer
  flattens every mesh to a direct child named after the MESH, so the engine's exact-name
  `GetChildByName(\"battle_model\")` hide can NEVER fire on an override — deployed daggers would
  render in FIELD too. Renaming the mesh in Blender is the keep-it escape hatch."
- The donor folder is SHARED: "Warnings name the shared-folder effect (every form loading the prefab
  picks the override up)."
- Per-form overlay hiding on export: "field/world forms hide `battle_model*` (old behavior,
  byte-identical exports); battle forms hide `field_model*` and KEEP the overlay; `GEO_MAIN_B0_001`
  hides both (HideZidaneOrichalcum)."
- Alt outfits (F3/F4/F5 ZDN → prefab 98): "Deploying them reskins the base outfit too → explicit
  warning (engine assigns alt art in code, bundle loads only)."
- Known cosmetic trade-off of a battle-form override: "battle Zidane loses the dagger overlay under
  a loose override, exactly like field-export overrides always did."
