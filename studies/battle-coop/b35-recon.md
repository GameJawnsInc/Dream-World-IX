### Corrections (verify pass)

THE CORE MECHANISM STANDS (hook inside CalcResult; always-emit at the Add(v) seam with a finally backstop; hoisted dmg_mot; raw Data.cur post-values; FIFO type-6 lane; main-thread List buffer flushed in Pump). Five material corrections:

1. THE PUMP FLUSH DESIGN MISREADS THE ELSE LEG (real design flaw). The answer: "in the else leg (:291-296) just Clear() -- a host F6-debug battle buffers frames ... they are discarded, never sent." But NetSyncBattle.cs:291 is `else if (_wasInBattle)` -- a ONE-SHOT transition edge, not an every-frame else. During a pure F6-debug battle, inBattle is false AND _wasInBattle is false, so the proposed Clear() never runs; up to 64 stale frames sit in _actionsOut and FLUSH ONTO THE WIRE the instant the next real battle sets inBattle=true (they carry the pre-bump nonce -- :273 increments _battleNonce on the rising edge, after which the flush happens -- wait, the flush foreach runs inside the same if(inBattle) block AFTER the bump, so the stale frames are sent under a live link and only the guest's nonce check saves the display). "Discarded, never sent" is false as designed. Concrete failure: host runs an F6 debug battle solo-testing (isDebug=true, :311 guard active but the emit at :310 fires), queues ~64 frames; host then enters a real co-op battle; 64 garbage action frames burst to the guest ahead of the first real one. ### Risks

- Legacy (non-SFXRework) SFX mode: fig is not cleared between effect points (only Figure Point consumes it), so a second hit's emitted fig.info can carry OR'd bits (e.g. MISS|DISP_HP) and fig.hp assignment overwrites — the emitted figure matches the host's own accumulated display, but guest-vs-host figure GROUPING can differ (host may show one combined number for two hits, the guest two).
- fig.modifiers (IFigurePointStatusScript — Trouble split figures, GradualPetrify) cannot ride the wire; guest figures lack those display adjustments unless the guest's own diorama statuses coincidentally match. Cosmetic only.
- Non-dying-boss band: the action lane carries raw hp (e.g. 9990 = logical 0) while the type-1 lane carries logical and the reconciler's 'HpCur==0 -> 1' clamp re-inflates to raw 10001 — the two lanes oscillate a boss inside its 10000-band by a few raw points. Invisible on the HUD (displays logical 0 either way) but the guest apply should use one consistent space per side (recommend: apply action frames raw for players, and for enemies convert or skip the cur write when the type-1 lane owns it) — decide at build time.
- Out-of-band HP writers bypass CalcResult entirely (poison/regen DoT ticks, countdown scripts, direct btl2d.Btl2dReqInstant callers): no action frame fires; those figures stay 150 ms-lagged type-1 territory. Known gap, not a regression.
- Emit ordering vs the mod tail: on the enemy-target normal path the emit at :310 fires BEFORE IOverloadOnBattleScriptEndScript (:323-325) — a Scripts-DLL end-hook that mutates HP after that point produces state the frame missed until the next type-1 sample. Same 150 ms class as today; do not chase it below the guard (player-target calls never reach there — the reason the law bans that hook).
- Fast-forward bursts: MainLoopUpdateCount battle frames per render frame times up-to-8 targets can approach the queue cap before one Pump flush; cap the action queue at 64 drop-oldest and log once per battle. Dropped frames self-heal via the type-1 lane (absolute values), losing only figures.
- Version bump to 9 hard-splits peers (established law — update both machines); the B3.2b party fields must ride the SAME bump or they burn a second split.
- QueueActionFrame must never throw (wrap internally): an exception escaping the finally would REPLACE the original exception inside CalcMain's catch and hide the real error from the log.
- cmd can be null in principle on exotic paths (CalcResult derefs v.Command.Data at :145 so today it never is by the time we emit, but the finally can run after a throw AT :145 — the serializer must null-check v.Command/v.Caster/v.Target defensively).

## INTERLEAVE — verdict: CORRECTED

### The verified answer

B3.5 INTERLEAVING DESIGN — one clock, one writer core, drain-before-reconcile.

(a) BUILD THE GUARD; the window is not acceptable. Quantified unguarded worst case: a pre-action type-1 sample applied after the action deltas persists until the next fresh seq = SampleMs 150 (NetSyncBattle.cs:48) + write tick 33 (NetSyncSocket.cs:507) + RTT + one guest frame ~= 200 ms LAN / ~280 ms relay. And it is worse than an up-flicker: a pre-action sample carrying Alive=true for a unit the action just killed enters the reconciler's REVIVE lane (NetSyncDiorama.cs:698-719) — RemoveStatus(Death) resets die_seq mid-fade, then the post-action sample re-kills: visible corpse-stand-up + death-animation restart. So the guard ships in the same commit as the action lane.

THE GUARD — a host-stamped seq horizon on a SHARED clock, not the guest-observed seq. The guest-side variant ("ignore until seq > the seq current at T") is usable but wrong in two corners: (i) late boot — _seqSeen resets per boot (NetSyncDiorama.cs:188), so an action frame drained before the first reconcile has no baseline; (ii) two actions with no host sample between them stamp the same horizon, so a sample taken between A1 and A2 (post-A1, pre-A2) passes A2's gate and regresses it. Instead:
  HOST: the v9 action frame carries `seqHorizon = _seq` stamped at emit, and THE EMIT ITSELF INCREMENTS `_seq` (the sampler's own counter, NetSyncBattle.cs:63, consumed at :463 `bw.Write(_seq++)`; expose an internal ConsumeSeq()). Samples and action emits now share one monotonic clock on the host main thread. Invariant (exact, thread-single): any type-1 sample with seq >= seqHorizon was taken AFTER this action applied (CalcResult writes HP above the emit line, SBattleCalculator.cs:264-289 -> FrameAppliedEffectList.Add at :310); any sample with seq < seqHorizon predates it. Correct regardless of Unity script-order between the battle update and the pump, and correct for A1/sample/A2 interleaves because A1's emit bumped the clock.
  GUEST: per btl_data wire slot (0-7, the same index space both the sampler :500-505 and ApplyUnit key on), keep UInt16 _gateSeq[8] + Boolean _gated[8]. Applying an action frame gates BOTH its caster and target slots with its seqHorizon. In ApplyUnit, pass the sample's seq down (available at NetSyncDiorama.cs:609-614) and if `_gated[u.Index] && (Int16)(seq - _gateSeq[u.Index]) < 0` skip the ENTIRE unit record (hp/mp/alive/revive/trance/ATB — not just hp/mp, or the death/revive lane regresses as above); else clear the gate and apply normally. Wrap-safe signed-diff compare (UInt16 wraps in ~2.7 h of continuous 150 ms sampling; gates also clear at Boot with the :188 reset block and on battle-nonce change).

==================== (5) THE FINAL ASSEMBLED APPLY ORDER (guest action-frame handler) ====================

Tick preconditions (main thread, between Pump and ReconcileTick): (0) frames queued && !Booted → drain-and-discard, return. (1) Booted: require Active && PHASE_NORMAL && load-status complete, else return WITHOUT draining. (2) Drain the FIFO in order inside the reconciler's try/once-per-boot-error-log pattern. Per frame:
  a. NONCE — frame.nonce != the booted wire nonce (or a manual F6 boot) → drop.
  b. RESOLVE caster + target slots → BTL_DATA via the reconciler's exact resolution (players by CompactedCharId, NetSyncDiorama.cs:650-660; enemies direct slot :662-667); slot 0xFF or no local actor → skip that unit (skip-log mask idiom), still process the other.
  c. DERIVE per unit from RAW wire hp only: lethal = (hpRaw==0); revive = (Death status set && hpRaw>0). Never from wire status bits.
  d. FIGURES FIRST (GetFreeEntry snapshots the bone transform at request time — the number must outlive the death fade): for target then caster, if the fig triple is nonzero AND the unit is not in _hiddenMask → `btl2d.Btl2dReq(d, new Btl2dParam { info=figInfo, hp=figHp, mp=figMp })` — hand-built, empty modifiers.
  e. MOTIONS (cosmetic, decided from wire lethality BEFORE any HP write): target flinch only if flags.dmgMot && !lethalT && !reviveT && dT.die_seq==0 && dT.bi.stop_anim==0 && !Death && !CheckStatus(FrozenAnimation) && !hidden → `btl_mot.SetDamageMotion(new BattleUnit(dT), null)` (slave-safe internally; guest fig.info==0 → no crit shove). Optional player-only caster swing: flags.casterIsPlayer && caster alive && same guards → `btl_mot.setMotion(dC, MP_ATTACK); dC.evt.animFrame = 0;`.
  f. TARGET STATE: lethal → if !Death, KillUnit(dT) (raw 0 + AlterStatus(Death) + same-tick SetDefaultIdle — never leave it to CheckPointData's next-frame unowned kill). revive → refuse enemy die_seq>=5; HP FIRST then RemoveStatus(Death). else plain: players `d.cur.hp = min(tgtHpRaw, d.max.hp)` raw; enemies raw against RAW max `d.cur.hp = min(tgtHpRaw, d.max.hp)` — BYPASS ApplyUnit's logical lanes; `d.cur.mp = min(tgtMpRaw, d.max.mp)` both.

Ordering laws: figures → motions → state → gate, inside each frame; frames in FIFO order; drain before reconcile. Death derives from raw hp + the type-1 lane only.
