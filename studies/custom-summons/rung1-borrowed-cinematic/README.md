# Custom Summons — rung 1: the borrowed cinematic

> Ladder position: `studies/custom-summons/PLAN.md` §5, rung 1 of 9 ("Borrowed cinematic").

## What this proves

That the full vanilla **Bahamut** battle cinematic (`ef227` full / `ef405` short) can be triggered
by a **minted ability on a non-Garnet/Eiko character**, cast from a **minted command** (not one of
the 3 hardcoded Summon-command ids), through the real battle HUD — with the FULL variant playing
**every time**, never the short one.

This is a `[[playable]]` bench, not new kit code: `Iviv` (the proven 13th-character example) casts
`Bahamut Cinema` from its existing minted "Spark" command (`BattleCommandId` 46). The one new
ability is a clone of stock Actions.csv row 62 (`Bahamut`; targets `AllEnemy(8)`, `vfx1=227`,
`vfx2=405`, `scriptId=85`, `power=88`, `mp=56`), with `targets`/`vfx1`/`vfx2` restated to prove the
kit's own binding writes the exact donor pair rather than a default, and because `targets` is the
load-bearing field: `btl_vfx.cs:99` only ever plays the short `vfx2` clip when `Target==ManyAny &&
cursor==0` (or a meteor-miss / short_summon / Beatrix special case), and Iviv's minted command never
enters `DecideSummonType` (that only fires for `BattleCommandId` 16/18/20 — Garnet/Phantom/Eiko's
real Summon commands, `btl_cmd.cs:1011-1029`). `AllEnemy(8)` is never `ManyAny`, so the full effect
227 is structurally unconditional here.

MP is kept **faithful at 56** (not overridden) — see the ability's comment block in
`rung1.field.toml` for the level-1 MaxMp arithmetic (Iviv boots 80/80 MP, 24 MP of headroom).

## Deploy

From the repo root, with FF9 **closed**:

```
py tools/deploy_field.py studies/custom-summons/rung1-borrowed-cinematic/rung1.field.toml --id 30300
```

`--id` is mandatory — a bare `deploy_field` call lands on the shared 4003 sandbox slot regardless of
the toml's own `id`. 30300 was verified free at recon time. The mod folder default (`FF9CustomMap`)
is correct for this bench.

## Playtest procedure (order matters)

1. **RELAUNCH FF9 entirely** (not `~` reload). The new CharacterParameters/BaseStats rows, the
   `CharacterDefaultName` directive, and the Actions.csv custom-ability rows (incl. `Bahamut
   Cinema`) all load at STARTUP / New-Game init. `~` Reload field only re-reads the field's own
   `.eb`/scene/walkmesh and will NOT pick any of this up.
2. **New Game.** This is what builds the party with CharacterId 12 (Iviv) present and boots every
   character's stats at level 1 (`FF9Play_Init` → `FF9Play_New` for every loaded
   `CharacterParameters` row).
3. **`~` → Warp to field → 30300.** `Main_Init` runs `B_PARTYADD(12)` on load — Iviv joins.
4. Walk around (the room has a random encounter, scene 67 — Evil Forest / Trail, the game's
   weakest) until a battle starts.
5. Select **Iviv** → command **Spark** → ability **Bahamut Cinema**.
6. **Expect:** the FULL vanilla Bahamut cinematic plays, including its native camera (Bahamut is one
   of the `FixedCameraEffects` summons — `SFXData.cs:1339-1369` — so it forces `UseCamera=true` and
   the .seq inherits Bahamut's real camera for free). Damage lands wherever the sequence's
   `EffectPoint` line sits (the donor's own timing, since the row is a verbatim clone).

## Success / failure modes

| Symptom | Meaning |
|---|---|
| Full cinematic plays, camera cuts to Bahamut's own shot, damage lands | **SUCCESS** — rung 1 closed |
| "Bahamut Cinema" is **greyed out** in the Spark menu | MP shortfall — re-check the level-1 MaxMp arithmetic in the ability's comment block (expected: not reproducible at the bench's stock stats, since 80 ≥ 56) |
| "Bahamut Cinema" is **missing** from the Spark menu entirely | You reloaded instead of relaunching, or skipped New Game — the Actions.csv/CommandSets/learn-file rows are startup-loaded |
| No cinematic (silent no-op, or a placeholder/no VFX) | The `vfx1`/binding failed — capture a few seconds of video and report it (`feedback-video-for-visual-bugs`) |
| Short Bahamut clip (405) instead of full (227) | Would falsify the `targets` claim above — check the deployed Actions.csv row's `targets` cell actually reads `AllEnemy(8)` |
