# NOVEL USES OF `.eb` — THE BOARD

`.eb` is not a scripting language with a few computed bits bolted on; it is a small machine whose expression evaluator is wired into *every operand of every instruction* (the argFlag byte), which owns a save-serialized array store with computed indexing (`0xD3`), and which can read values the engine recomputes every frame for free. This project has spent it almost entirely as a **sequencer** — do this, then that, gated on a bit — which is exactly why the kit's vocabulary is rich in verbs and poor in state, sensors, time and output. Four axes are essentially untouched: the argFlag lane aimed at anything other than a warp or a text value; the vector store used as a **time** axis rather than a table (and the kit's own re-seed law is what has kept it a table); the engine's own per-frame computations — which triangle you are standing on, who is looking at whom, a sine table, another object's live transform — **read** rather than re-implemented; and `.eb` as an **outbound** channel, which is why the game still has no way to tell the toolkit what actually happened. The weak axes are not short of mechanisms. They are short of memory, sensors and a way to report.

## THE TOP 10

### 1. The Persistent Table — a vector class exempt from the re-seed
Every `gScriptVector` table the kit emits is force-wiped (`size←0` then `size←n`) at every `Main_Init`, by a deliberate law that makes the save-global id namespace harmless. That same law is why nothing in the kit remembers anything the flags cannot: no ordering, no counts, no trajectories, no logs, no "how many times". One new table class turns the vector store from a per-session scratchpad into the project's first author-owned durable structure — and it is the substrate under a dozen other entries on this board (ledgers, ghosts, rings, split times, offstage agents, the roll stream).
**How:** `persist = true` on `[[behavior.table]]`, allocated from a **reserved tid band** the auto-allocator and any explicit `id =` are refused from (the band split is enforced at the allocator, not in a docstring); cell 0 holds a magic+schema word checked before the first read, mismatch ⇒ `ClearMemoriaVector 0x11A` + reseed; writes stay on the proven `<tid> B_VECTOR_SIZE <n> B_LET` grow + `<tid> <idx> B_VECTOR <v> B_LET` pair; values fenced to ±2²⁵.
**Cost:** medium; **stock**. Rung 0 is free and decisive and has never been run: write ten cells, hard-quit, relaunch, load, read back. `gScriptVector` save-serialization is *sourced* (`JsonParser.cs:521-545`) and *never once observed* in this project.

### 2. Ask the engine where the actor is — `B_BGIID` / `B_BGIFLOOR`
Two expression tokens, fully decoded, arity-mapped, and emitted by nothing, that hand a script the walkmesh triangle and floor under an actor — a value the engine already recomputes every frame. Path B was falsified on *computing* point-in-region in RPN; this computes nothing, it reads the collision result and indexes a table. One HUD row settles the only real question: does the arity-1 operand resolve an arbitrary actor UID or only the controlled character — and either answer is worth having, because "player only" lets you close the Path-B rung for good, and "any actor" un-falsifies its §5.
**How:** `expr:const(0) B_BGIID` in a `[[behavior.hud]]` slot, walked over ≥10 points whose offline triangle index is predicted by `BgiWalkmesh._pt_in_tri_xz`. Then key a build-time property table on `(floor, tri)` via nested `B_VECTOR` — 25/100 census fields have XZ-overlapping floors, so `tri` alone aliases by construction. Payoffs: precomputed LOS stealth masks (24-bit, ≤24 static posts), damage/ice/mud floors, surface footsteps, room-aware music, per-triangle wear.
**Cost:** rung 0 is one TOML line and one deploy; **stock** on a novel field. The sentinel is −1 off-mesh, so every read is wrapped in the shipped `E E const(0) B_GE B_MULT` clamp or it throws once per rendered frame.
**Shipped** as the `[behavior]` floor sensors `on_floor` / `same_floor` / `other_floor` + a `floor:<who>` HUD source (with THE FLOOR-MAJOR TRIANGLE LAW and the fork walkmesh-literal lint), rungs 0-1 in-game proven → [`../walkmesh-sensor/PLAN.md`](../walkmesh-sensor/PLAN.md). Three corrections to the entry above: `const(0)` reads **Main** (uid 0, never an actor) and returns −1 forever — the player is `B_PTR(250)`, a kit NPC its entry slot, and any actor UID resolves (Path B §5 un-falsified as a *read*); triangle ids are **global** in file order, not per floor; and the −1 sentinel does not throw in a HUD `expr` slot — the clamp is needed only where the value indexes something (`[TEXT=]`). A condition must never read the token directly: it runs in the ticker's mirror block only, and −1 is UNKNOWN, never a floor.

### 3. The story-write trace — ground truth for narrative state
**Rung 0 in-game proven** (11/11: every script write on stock Lindblum 552 joined to its store) → [`../story-trace/PLAN.md`](../story-trace/PLAN.md). The correction to the entry below: a per-frame memcmp cannot name the writer, so s88 hooks the one script store (`EBin.SetVariableValueInternal`) and keeps the memcmp only as the net for C# writers; and its falsifier cannot fail as written, so rung 2 (the null pair) replaces it.
The narrative-state arc's blind spot is *attribution*: naive byte-adjacency covers 32.6% of 12,322 bit-write sites and the rung-0 prediction is dominance lifting it past ~55%. A per-frame `memcmp` of a shadow copy of `gEventGlobal`, lifted from `NetSyncState.SnapshotStory` rather than written fresh and drained through `HarnessAgent`'s existing publication, gives **exact, ordered** ground truth for every path actually played. Run the same harness scenario twice — once on the fork, once on the stock donor at the same beat — and the deliverable is the per-function set difference: what the stock field runs that the fork never reaches. That is the evidence `FORK_FIDELITY.md`'s worklist currently asserts by hand.
**How:** shadow `Byte[2048]` + one memcmp/frame; emit `(frame, byte, new, EffectiveFieldId, ScenarioCounter)`; mask from `flags.BIT_REGIONS` — not a hand-listed pair of bands (read-mail 8512-8711, Mognet locks 8376-8511, the mailbox at bytes 1024-1045, choice scratch, and above all the netsync cells at 2032-2039 which are rewritten *every frame* under co-op); explicit resync + ONE epoch marker on save-load, on `Array.Clear`, and on `ApplyStoryBeforeEvents`, or each floods ~2048 rows and evicts exactly the donor-attributed writes it exists to capture. `ScenarioCounter` lives at bytes 0-1, so every advance self-reports.
**Cost:** medium; **dwix** (one patch, dormant by default, `state.json`/`events.jsonl` as the sink — no new `.eb` surface, no new sysvar). Falsifier in one round: replay the known-good verbatim Lindblum 552 @ SC 3115 / byte 236 = 0x0F calibration and check the write *order* reproduces; if a traced run tightens no interval the save corpus already gave, it is refuted on its own terms.

### 4. The fight writes the ledger
Battle `.eb` runs on the same `EventEngine` and the same expression layer, and the engine **suspends** field objects across a battle rather than reloading them — so `Main_Init` never re-runs and cannot clobber what the fight wrote. That makes enemy AI a *producer* of narrative state: who fell first, which phase you reached, how much the boss had left, read back by the catching field's tag-10 `Main_Reinit` and narrated instead of a generic victory line. Every shipped field↔battle seam runs one direction only (pick a scene, pick music, handle losing); this is the return path.
**How:** the tag-9 (Dying) body and the tag-5 attack executor append a packed Int24 row (`kind<<20 | who<<12 | payload`) with the grow-then-write pair; values come from `B_SYSLIST[1] B_MEMBER(41/36/35)` — **never** `B_CURHP`, which is a party-slot `GetPlayer` read on a different axis; read back with a `B_VECTOR_SIZE` switch plus `set_text_variable_expr`. Ledger tid comes from the reserved band (entry 1), never the 1000+ auto band a `[behavior]` field will wipe on entry.
**Cost:** medium; **stock**. Two honest bench unknowns: does tag-9 dispatch reliably for the *last* enemy killed, and is `B_SYSLIST[1]` the dying unit inside a tag-9 body. Do not pitch the one-bit degenerate version as the fallback — that is `[deathrules]`, already shipped.

### 5. The roll stream — a seeded PRNG in pure RPN
Every random draw in the kit is `B_SYSVAR[0]` (`Comn.random8`) — impure, shared with the engine, unseedable — which is why no kit content is reproducible, why a pooled-unit bench cannot be re-run, and why the dialogue census files RNG as structurally unfixable for co-op mirroring. A Lehmer recurrence over one save-backed cell gives a deterministic, shareable, **offline-replayable** stream; and because the recurrence is pure and 26-bit-bounded, the kit's own `eb_eval` interpreter can predict the exact in-game sequence at build time. That is the single narrow case in this project where a gate genuinely *is* an oracle.
**How:** `x' = a·x mod m` chosen to the envelope — `a·m < 2^25`, so `m = 32749` with a primitive root (13 is full-period with ~79× headroom); state that a textbook MINSTD is **unrepresentable here** at the call site or the next author will reach for it. The advance is its own `0x05` statement, never a HUD/choice value (`exprsem` refuses WRITE/IMPURE there, correctly). Build-time refusal of seed 0 (a fixed point), of an overflowing multiplier, and of a `const(N) B_REM` whose modulo bias exceeds a threshold.
**Cost:** small; **stock**. State lives on entry 1's persistent lane. Prove it on the cheapest existing consumer — swap one `wander` unit and show two `~ Reload`s walking the identical path. Rename it: "seed" is taken by `story-seed`.
**Shipped** as `[[behavior.stream]]` + a branch `roll` (+ `wander` `seed`), rungs 0-1 in-game proven → [`../roll-stream/PLAN.md`](../roll-stream/PLAN.md). Two corrections to the entry above: the generator is `236 · x mod 65537` (full period 65536; 13 mod 32749 falls on 13 lines, and 237 has a lag-2 lattice), and the oracle is `content/rollstream.py`, cross-checked against the `.eb` interpreter for all 65536 states.

### 6. The gaze graph — attention the engine evaluates for free
`SetHeadFocusMask` is an 8-bit **directional** adjacency the engine evaluates every frame at 31-2000u, and the kit ships it only as a per-model invariant harvested into defaults. Authored, it is a social layer at zero per-tick script cost: two NPCs watching each other until you walk in, guards watching a door instead of you, every head in the market snapping to the crate you just moved (chests already carry a SelfMask, so props are lawful targets). Re-emitted at runtime from a talk handler or a flag branch, attention becomes a state machine — the conspirator who watches the door until the flag flips, then watches you.
**How:** `0x8B SetHeadFocusMask(SelfMask, TargetMask)`; A turns toward B iff `A.Target & B.Self`. Budget it honestly: this is a **biclique cover of rank ≤8**, not an adjacency matrix, and stock already spends bit 0 (player) and bit 6 (NPC-watches-NPC — 100 SelfMasks / 40 TargetMasks across 156 rigs), leaving ~4 free channels, so author *groups*, never per-pair edges. `0x8B` is self-scoped, so a runtime flip goes by uid through `RunScriptAsync`; the O(1) crowd form is one re-emit in uid 250's own context from a region tag-2 enter, which relights every NPC carrying that zone bit.
**Cost:** small; **stock**, 4 bytes per actor. `FollowFocus 0x91` (body turn) is the one unproven piece and permanently overrides an authored `face`.

### 7. The sine kit — motion you compute, not keyframe
Nothing in the kit moves by computation: cutscenes are keyframed walks through `pathfind.py`, platforms ride authored waypoints. But `B_SIN` is `ff9.rsin(getv() << 4)`, so its period is **256 units per turn** — the same byte angle `TurnInstant` takes — and its amplitude is **±4096**. The calibration is therefore *derived, not benched*: `x = cx + B_SIN(t·s + i·k)·r/4096` puts `r` in world units directly, and `r ≤ 8191` keeps the product inside the envelope on a field ~4000u wide. Orbit, pendulum, float-bob, spiral ascent and a wave travelling down a row of NPCs all fall out of one shared clock, and the *same counter drives facing* with no conversion, because the unit is already the facing byte.
**How:** one daemon does `MAP.I16[t] = (MAP.I16[t] + 1) & 255` — the mask is mandatory, unmasked it wraps negative at 32767 and feeds `rsin` a negative angle; N prop loops read it with a compile-time `i·k` offset, so a crowd is phase-locked with zero per-actor state. Emit raw: `encode(0xA1, x_expr, neg_y_expr, z_expr, arg_flags=0b111)` — **operand 1 is negated height, operand 2 is world Z**, and getting that backwards reads as a prop sinking through the floor. Props need `SetObjectFlags(7)` + `SetPathing(0)` + a literal rest-pose re-assert, because `CreateObject` floor-places first.
**Cost:** small; **stock**, and it is a net `.eb` byte *reduction* against a stored path. Walkers keep pathing and ride `0xBF` (x/z only, engine re-grounds), so bob and spiral are prop-only; orbit and pendulum work on both.

### 8. Photo mode — the decoupled frame
FF9 has no free camera anywhere, and the kit emits only `SetFieldCamera` and `EnableCameraServices`. A poller that takes the scroll target away from the player and hands it back as a pannable box inside the active BGCAM's own vrp window — plus hide-actors-one-at-a-time and a held colour grade — is the first player-driven camera in the game. It is also the instrument this project has never had for its hardest recurring question: whether authored content actually lands on the painted art, answered by a human panning the frame and dissolving the cast, rather than by a gate that went 0-for-13.
**How:** `0x71 EnableCameraServices(0,0,0)` (the study-proven follow master switch, already emitted) rather than the undecoded `0x73/0x74`; `0x6F MoveCamera(destX, destY, dur, type)` with destX/destY as `{}` RPN over two scratch Int16s driven from a `B_KEY` poll; clamp **in script** against build-time vrp bounds instead of trusting `0x1E SetCameraBounds`; `0x39/0x3A/0xD5` for the actor sweep; `0x70` + re-enable to restore. Build-time **hard refusal** on a field whose pan box is degenerate, reporting the box in pixels.
**Cost:** medium; **stock**. Two inherited traps: every window it opens carries `[NTUR]` or a latched F9 turbo dismisses it on frame 1, and SELECT is contended by `[[ate]]`, `[siege]` and the behavior hire poller — make the open button author-set and lint the collision.
**Rungs 0-1 in-game proven**: rung 0 (154/154, six harness runs, owner-playtested) and rung 1, the kit feature
`[photo]` (16/16 twice on bench 30956) → [`../photo-mode/PLAN.md`](../photo-mode/PLAN.md). Corrections to the entry above:
- **The rig breaks at its first step.** `0x71 EnableCameraServices(0,0,0)` clears the field's Active bit, and every later `MoveCamera` is silently dropped (proven in-game as a negative control).
- **`MoveCamera` itself takes the camera.** A finished move HOLDS, follow stays off, and `ReleaseCamera` alone hands it back.
- **The engine does not do the clamping the entry relies on.** It never clamps Y. It clamps X only at issue, to a widescreen-narrowed window, and `SetCameraBounds` does not bound `MoveCamera` at all. So the script clamps.
- **`0x73`/`0x74` are the clamp lock and unlock, not follow switches.

### 9. The Unseen — perception as content
The kit ships chase behaviour and no perception layer. A pursuer whose model is hidden the entire time, tracked only by a dark shape on the floor, panned footsteps, and where the room stops being safe, is a register FF9 never uses, and every opcode it needs is stock. Scope it as one flag on the shipped stalker class — `unseen = true` — not a system; the sticky Cooldown-150 tree underneath stays untouched, so the arc mints no pursuit surface.
**How:** `HideObject 0x3A` (the proven ferry-departure idiom) + `EnableShadow 0x7F` + `SetShadowAmplifier 0x85` on the same uid; evidence rides the existing `sfx` leaf with `RunSoundCode3 0xC8`'s pan/volume as **expression** operands computed from the chaser's x/z against the player's — the in-game-proven chest SFX path, so no new audio lane. Claim it honestly: the substrate scales a textured quad, so the dread comes from the blob's **size and closing rate**, not a silhouette. Hysteresis is mandatory (engage on TRIGGER, hold on KEEP) or the cue strobes at the standoff radius and reads as a bug.
**Cost:** small; **stock**. One confirmation bench (does mesh-hide preserve the shadow — `savepoint.py` already toggles the two separately for the airborne moogle); fallbacks are `SetModelColor`, then a shadow-only prop mirrored to the chaser's coords. **Vibration is out, not deferred**: on a field with no vib blob the rumble ops throw inside `DoEventCode` and abort the event frame (the s62 bug). Ship the dividend — an `eblint` rule refusing `0xF6`-`0xFC` where the event name has no vib data.

### 10. Quantize the board
Every combat lane the kit ships is real-time with continuous positions, which is precisely why Path B's membership wall exists. A board deletes the wall by deleting free movement: the script owns every unit's cell index, so "where is this unit" is a table read rather than a geometry query, and `MoveInstant`-teleport — the thing that killed incremental tracking — becomes the *normal* move instead of the desync source. Cell indices are the arithmetic the 26-bit CalcStack is actually good at; world XZ crosses into cell space exactly once, offline, in the baked table.
**How:** hard compiler rule — **no world coordinate may enter any expression**, or it is Path B wearing a hat. Pooled actors snapped by `0xAD MoveInstantXZYEx` (plain `0xA1` moves only the executing entry's own actor, so 16 pieces would cost 16 entries); BFS frontier spread one expansion per tick across `[[behavior.scan]]`'s live-index loop; dispatch `0x05 SET` then `0x06/0x0B` with every arm laid forward of the anchor. Render with pooled stock `floor_tile` props before minting per-cell overlays, and note `TABLE_MAX_LEN = 64` is kit policy — 8×8 sits exactly on it.
**Cost:** large; **stock**. Rung 0 is one falsifiable playtest: 6×6 board, three units, tap-to-select, tick-spread BFS range paint, one move. Design the battle handoff *first* — `0x2A` returns through tag-10 with every object suspended and entry locals and placements gone, so the board re-hydrates from the vectors or v1 never calls `0x2A`. Pick a near-top-down donor (559, pitch 68.8) or the lattice will not read.

## THE REST, BY THEME

### A. The argFlag lane, pointed somewhere new
*Any operand of any op ≥0x10 with args can be an RPN blob. The kit flags it on a handful; stock flags it on almost none, which is a warning as much as an opening.*

- **Score by lookup table** — the same room scores itself by beat/party/outcome; the song id is a vector read, not a build-time int. Emit the **pair** (`1792` LOAD then `0` PLAY) with the *same* index or the old track stays resident — the Ice Cavern fork bug. `0xC5`, `B_VECTOR`.
- **Boss rush on a computed `Battle()`** — the fight ladder as data; `0x2A` is an `adFin` terminator so the chain is a tag-10 trampoline, not a loop, and the one-shot latch in `content/behavior.Battle` must be deliberately defeated. `0x2A` arg_flags=0b10, `B_VECTOR_SIZE` as the exit.
- **The boss that changes arenas** — each phase a real scene with its own arena and model, chained through the same trampoline with `ContinueBattleMusic` carrying BGM across the boundary; sell it on *arena change*, not "no black screen", since tag-10 runs after the field restore. `0x1B`, `0x2A`.
- **Tension and the loot expression** — `AddItem` with a computed id is the kit's one genuinely unexercised argFlag atom (every one of 37 call sites is `0x66/0xCE/0x7C/0xE7/0x59`, never `0x48`); weighted catch tables fall out. Clamp the index against `B_VECTOR_SIZE` and remember `id % 1000 >= 612` is the engine's no-op rule. `0x48`.
- **Checksummed share codes** — two 4-digit steppers (the shipped cap) validated mod-97 on the parts, because `hi*10000+lo` overflows and re-tags rather than wrapping; `10^4 mod 97 = 9`. A typo is refused instead of silently building a different room. `B_REM`, `0x0B`.
- **Visited-only fast travel** — the destination list IS the availability mask: each arrival ORs its bit, the hub emits one `enable_dialog_choices_var`; 16 rows per hub, page past that. `0x7C`, `or_var` (T_OR_ASSIGN 0x3F).
- **The comfort bus** — difficulty and flash intensity read from a player-set GLOB profile instead of baked immediates: a photosensitivity damper fenced to the **ADD** channel only (damping SUB deletes the transition), a QTE assist dial on `window` + `par_max` together. `0xEC` operands 3/4/5, `0x22`.
- **Control twist as a status effect** — a per-tick computed `SetControlDirection` is vertigo, an escalating curse, a drift; `B_SIN` on an owned tick counter masked to 0-255, seated outside `Main_Init` so the "exactly one TWIST" precondition holds. Census stock for any 0x67 outside an init body first. `0x67`.
- **Over-hunted zones** — encounter *composition* as a depletable population: re-issue `SetRandomBattles` with all four slots on one species so the next kill is knowable, decrement on the tag-10 return behind a scripted-battle latch. `0x3C`, `0x57`, `ProcessEncount` integrates along the path so a trodden route really is safer.
- **The loadout stack** — push level/gear into a vector, overwrite for a scene, pop on exit; scope it to **level** until a read lane for exp and equipment exists (`flex(13,1)` is the only proven per-character read). `0x112/0x113/0x114`.
- **The MPOS lattice** — `[MPOS]` is baked, but the window's *text id* operand is not, so one authored line at N positions is a window that re-anchors on a beat. A discrete re-anchor, never per-frame: `NewMesWin` disposes and recreates, replaying the grow animation. `0x20` arg_flags=0b100.
- **Scarcity merchant** — a counter you haggle at where the price is computed at Confirm from a stock level the world drew down; `remove_gil_var` is the only new emitter, and it must clamp 1..32767 in the expression because `getv3u` casts unsigned and a negative price *adds* gil. `0xCF`, `B_SYSVAR[6]`.
- **The gramophone that remembers** — a save-backed song pick replayed in `Main_Init` and tag-10; the kit's first player-written durable value. `0xC5` with a `Global.UInt16` operand, `0xDE`.

### B. The save as a data structure
*Everything here rides entry 1. The re-seed law is the only thing standing between the kit and a memory — and it exists for a good reason, so the exception must be a named class with its own id band and its own lint, not a flag.*

- **The continuity ledger** — flags record *what*; an append-only beat log records *in what order* and *how many times*. Must be enrichment, never a gate: `gScriptVector` rides only the Memoria extra save, so a lost sidecar must degrade to today's behaviour, not break the story.
- **Cross-field consequence ledger** — a bounded ring of optional acts in GLOB bytes (8 slots + cursor + lifetime count) so an NPC can mean *the most recent one*; explicitly not for beats ScenarioCounter already orders.
- **Split ledger and PB delta** — real speedrun splits with a live ±, clocked by `B_SYSVAR[20]` (global, monotonic, save-backed) and never the `Wait(1)` counter, which stalls across battles and menus. The in-game half of a feature Memoria already has the outward half of.
- **Travelling leaderboard** — top-ten rows sorted by the shipped `engage nearest` argmin idiom (conditional-negate, conditional-copy) plus a shift; the sort is the reuse, the persistence is the new part.
- **The trace runner / ghost racer** — record the player's path, replay it on a tinted second actor. Drop "translucent": `0x8F` is CHRCOLOR with no alpha. Use `0xAD` not `0xBF` (which hardcodes Y=32768 → topmost overlapping triangle), drive the clip explicitly or it foot-slides, and stamp FieldTPS into cell 0 since pace is TPS-relative.
- **Follow-the-leader ring buffer** — a segmented creature where segment *i* is **delayed**, not offset, so the body snakes through the turns the head made; stride 4 and the 4th slot is *facing copied verbatim* (`obj(uid).f[3]`), not an angle you compute.
- **The deferred event heap** — "fire this in ten minutes of play" keyed on `B_SYSVAR[20]`; honest cadence is "at the next entry to an instrumented field at or after T", which is `[[on_entry]]` with a numeric gate — and that collapse is the finding.
- **The sparse dictionary ledger** — `B_DICTIONARY` (flex 22,2) has zero call sites anywhere; the two unknowns are the write path and, load-bearing, whether a **miss** returns 0 or throws.
- **Vector schema version guard** — a magic+version cell in a dedicated *guard* vector (not cell 0 of the payload, which the ticker's hot loop then has to `B_PLUS` past); HDR written **last** so a torn migration re-migrates.
- **The level/exp capsule** — `0x113/0x114` are the only in-game writers of level and exp, and the narrative-state arc's derived mid-story boot currently hands the player a level-1 party in a disc-3 scene. Equipment and bag already ship via CSV; this is the one uncovered axis.
- **Practice mode: the snapshot ring** — capture only what the expression layer can read (per-slot HP/MP, gil, position, a declared item list), latch the slot→character map via `flex(10,1)` and **refuse** a restore whose map drifted. A checkpoint ring, not a savestate — say so.
- **Black-box flight recorder** — telemetry into the save so a bug report is a file; loses exactly the crash/softlock class it advertises, because the player cannot reach a save point.
- **Demand-scoped heap snapshot** — a what-if sandbox is tractable because the median field reads ONE GLOB bit; store the restore set as **mirror bits** in gEventGlobal, not a vector, and make the branch *sealed* (one exit, no battles, no savepoint) rather than guarded.
- **Play-by-mail duel** — async PvP by splicing only the match record between two extra-saves; the transport is new, the payload format is the s37 state-mirror lane.
- **Message stones** — player-authored notes from phrase banks; the genuinely missing piece is a **narrow, self-describing, checksummed band codec** that refuses any bit outside its region, which is the guarded lane beside `save-edit` that does not exist.
- **The save-boundary census** — three verdicts per cell (rides the save / does not / is not state), offline first from `JsonParser.cs` × the three read surfaces, benching only the ambiguous ones; the correctness map narrative-state and co-op currently answer by guessing.
- **Every NPC remembers** — a per-character memory cell keyed by an *authored* identity id (never field×uid, which names a room slot), costing zero story-flag bits.
- **Ring-buffer message bus** — objects post instead of squatting on shared GLOB cells; the real deliverable is per-consumer tails, which is what makes fan-out cost bytes in *readers* rather than in sender×receiver pairs.

### C. Sensors, and what the world does while you are elsewhere
- **Floor-ID caption channel** — a per-tick `B_BGIFLOOR` into a `[TEXT=bank,slot]` strip: an elevation/orientation readout for low-vision play, on multi-floor rooms where the number is free. Reserve row 0 as "off the path" so the clamp's floor-to-zero *means* something.
- **The desire path map** — the ground remembers where you walk; wear per triangle feeds encounter rate (which **integrates** along the path via `_encountBase`), NPC routes, and trodden-state overlay swaps. Rides entry 2 + entry 1.

## THREE CHEAP FIRST MOVES

**1. One HUD row: `expr:const(0) B_BGIID` (+ `B_BGIFLOOR`, + the same read for a non-player uid).**
One TOML line on a scratch bench, one deploy, four slots published at once. It answers four things in a single playtest: is the token live at all; is its operand an actor or something else; does the runtime id match the kit's offline triangle index; and what comes back off-mesh. A positive on the non-player slot un-falsifies Path B §5 and retires a sentence that has been doing more work than its evidence supports. A negative closes it for good and writes one line into the rung. Either way it gates entries 2, 9 and half of theme C.

**2. The persistent-vector round trip.**
Write ten cells at a reserved tid, announce them, hard-quit to desktop, relaunch, load the save, read them back. `gScriptVector`'s save-serialization is cited in four places in this repo and has never been observed once, and the only shipped consumer *erases it on every field entry by design*. This single test gates entry 1 and, through it, roughly twenty ideas on this board — every ledger, ring, trajectory, split table, stream state and offstage agent. If it fails, the whole family collapses to within-session gimmicks and no amount of cleverness upstream rescues it.

**3. The battle-side lvalue probe.**
One bench enemy, one row: does `<tid> <idx> B_VECTOR <v> B_LET` execute from a battle `.eb` body, and does a field read it back after the return? `exprsem` records every defined `flexible_varfunc` as a pure READ per `EBin.cs:2388-2414`, so "battle shares the expression layer verbatim" is currently a wish. It is the whole premise of entry 4 — the only idea on the board that makes the battle a *producer* of narrative state.

All three ride one bench session. **Free rider, no game needed:** while the install is closed, open `EventEngine.DoEventCode.cs` in the clone and read the case bodies for `0x88 RunModelCode`, `0x8F`, `0x3E`, `0x76`-`0x79` and `0x11C` in one sitting. ## WHAT THE VERIFIERS KILLED

**DrawRegion (`0x76`-`0x79`) — the scissor stack.** Pitched three separate times, refuted three times. The mnemonics were harvested from Memoria's *case-label comments* by a regex, not from bodies; `0x79` is literally named `"0x79"`, Memoria's convention for a slot whose semantics it never recovered. The arg shape (2×u16, 2×u16, zero, zero) reads as a list-builder, not a nesting rect stack. Worse, the headline payoff is a settled negative: letterboxing in this engine is `NarrowMapList.MapWidth`, a static fldMapNo table, which is precisely why `s23` had to be written. And under the stub hypothesis "nothing visibly happened" is indistinguishable from "I emitted it wrong". *What survives: a 20-minute source read with three possible verdicts, two of which close the arc for free.*

**`B_FRAME` as a free-running clock.** The most expensive misread on the board. `B_FRAME` is `GetCharAnimFrame(gCur.go, getv())` — it returns `round(clip.length × clip.frameRate) + 1`, i.e. the **length of an animation clip**, static, −1 if the object has no clip by that name. It does not advance. That kills the parry window, the knock-rhythm lock and the phase clock outright, and the proposed RPN was additionally malformed (arity-1 `B_FRAME` swallowing its own timestamp operand, leaving an empty-CalcStack pop — the per-frame desync class that has already cost this project a session). There is **no sub-second clock in stock `.eb` at all**: sysvar 20 is seconds, 17 is only live during a scripted countdown. The repo's own dialogue census files `0x6A` under "TIMING"; that label is wrong and should be fixed independently.

**Positional field SFX.** `AllSoundDispatchPlayer.FF9SOUND_SNDEFFECT_PLAY(ObjNo, attr, pos, vol)` accepts `pos` and never uses it; every pan sound-code in `FF9Snd.cs` is a stubbed logging case. `SetSoundPosition`/`SetSoundObjectPosition` turn out to be pure *calculators* that project a point through the camera and stash a pan/volume pair in two sysvars for a later script read — no handle, no attachment, no follow. And the pan operand is already on the wire and already inert: the kit has been passing `128` at five call sites for the life of the project. Stereo field audio needs a DLL patch, and the patch is small and well-shaped — but it is a patch.

**`SetFieldName` as a menu or save-slot label.** Pitched three times. `0xB0` writes `FF9StateSystem.Common.FF9.mapNameStr`, and `MainMenuUI`'s **Field** arm never reads it — it reads `FieldLocationName(fldMapNo)`, which is the exact line `s33` repointed. `mapNameStr` is the *else* branch (neither Field nor World). The one player-visible surface `0xB0` provably reaches on our build is `PlayerWindow.SetTitle` — the OS window title bar.

**A room that is moving.** The Lindblum lift (field 2151) is already decoded in-repo as stock's own scroll illusion — player stationary, BG tile loops, then a real `Field()` re-entry — and `FORK_IDGATE_MAP.md` already enumerates the ~24 donors that ship a loop/parallax overlay. `import --verbatim` on any of them yields a moving-background room *today*, with zero new opcodes.

**Rumble.** On a novel field `vib.Parms.vibPtr` is null by construction (the blob is keyed on the donor's EventDB name), and the unguarded ops throw `Nullable.get_Value` inside `DoEventCode`, aborting the whole event frame — which is the exact bug `s62` was written to stop, on forked cargo-ship fields. Compounding it: there is no script-readable predicate for "this player has a pad" or "vibration is on in Config", so rumble can be a redundant accent on an already-visible cue and can never be the sole carrier of information — which is precisely what "a tell you feel and never see" asks of it.

**The afterimage / any translucency.** Field GEO models are force-assigned `Unlit/Transparent Cutout` — a binary alpha *discard*, not blending — and `0x8F SetModelColor` is `(uid, r, g, b)` with no alpha, multiplying about a neutral of 128. So the substrate yields four fully opaque duplicates of your character, variously darkened: a conga line, not a smear. The same fact kills "translucent ghost" wherever it appears on this board.

**A fight you win by talking.** The mechanism is real; the *sensor* is not. `_membertable` — the transcribed complete `GetCharacterData` switch — has no command, last-action or idle selector, so "the player chose not to attack" is not legible to enemy AI at all. The proposed fallback (boss HP unchanged for two ticks) reads true for a miss, a Defend, a heal, a buff, an absorbed element and, fatally, for a party still sitting in the command menu — so the mechanic would fire on inattention rather than intent. `TerminateBattle 0xE1` is additionally a name with zero call sites, zero described semantics, and zero operands with which to select an outcome.

**The name lane** (read back the name / the guestbook slot / the name it takes from you). `Menu(1, char)` commits the typed string into a real `PLAYER.Name` in the save, `NameSettingUI`'s hardcoded `<12` reseed makes any custom `CharacterId` a corrupter, only ids 0-7 have a renderable text tag, the harness is declared unable to drive `UIInput` typing, and `Configuration.Hacks.DisableNameChoice` deletes the prompt outright for the players who set it. The one claim nobody could verify either way — whether a bare `SetName` with no following prompt writes the name or merely *seeds the widget* — is the one the whole idea rests on.

**The 26-bit overflow prover.** Already shipped, and shipped with the same justification, in the same words: `journal.eb_bounds` is an interval evaluator over RPN with per-leaf bounds and per-operator transfer functions, wired to `EXPR_VALUE_MIN/MAX` at four lint sites and pinned by tests, and its docstring cites "a docstring saying 'mind the ceiling' is a wish" verbatim. What survives is one rule (the `B_LET` destination width) and one refactor.

**The whole instruments-and-compilers class,** refuted almost uniformly on prior art rather than on substrate: the `[[assert]]` block, tile-colour telemetry, breadcrumbs and the watchdog, the flight recorder, the fork execution histogram, the ISA conformance sweep, the self-writing probe field and the LiveSplit beacon all describe channels the s83 harness, the s22 debug menu's Flags/Batch tab, the battle telemetry JSONL, and Memoria's own `AutoSplitterPipe` already own — usually at higher bandwidth and without spending `.eb` bytes inside the field under diagnosis. Likewise the `.ebo` linker, the peephole optimizer, statecharts-to-switch, ink/Yarn import and the IR with a register allocator: the kit already has `cfg.py`'s dominators, `exprsem`'s effect analysis, `labelasm`'s island relaxation, the byte-exact `ebsrc` round trip, and byte-grounded switch emitters. The honest residue across that entire class is three small things — the store-width rule, a budget column on four existing surfaces, and a cross-field vector-id arbiter — not a toolchain.
