## 1. The Floor-ID Caption Channel

**Status:** SURVIVED · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** A per-tick read of the walkmesh triangle/floor under the player becomes a captioning and orientation channel: surface-change captions ("*gravel*", "*water*", "*wooden stair*") for deaf/HoH players, and an audio-free "am I still on the path" tell for low-vision players. It reads a number the engine already computes every frame, with no regions, no triggers, and no new flags.

**Mechanism (as proposed).** `B_BGIFLOOR` (expr token 113, arity 1, READ per `eb/exprsem.py:163`) and `B_BGIID` (112) return the floor index / triangle id under a uid. A seated ticker entry (the `content/behavior.py` central-ticker shape: one entry looping `Wait(1)`) evaluates `const(250) B_BGIFLOOR` into `Map.Byte[cur]`, compares against `Map.Byte[last]` with `B_NE`, and on change does `SetTextVariable(0, Map.Byte[cur])` (0x66 in its expression form, arg_flags=0b10) + `WindowAsync` (0x20) on a `[[text_table]]` `[TBLE=]` bank whose row index IS the floor id — so one `.mes` entry holds every surface caption and the value selects the row. Optional `RunSoundCode` (0xC5) on the same edge gives the footstep variant. Because `B_BGIFLOOR` is READ it already passes `hud_expr_tokens`' WRITE/IMPURE refusal, so it can ride `[[behavior.hud]] expr:` with zero new validator work. Cost is one Map.Byte pair, no GLOB, no flag band.

**Mechanism (screen correction).** Three concrete fixes. (a) The tag is `[TEXT=<bank>,<slot>]` (`content/texttable.py`), not `[ITEM=]`-style; use a named `[[text_table]]` bank so the build allocates the txid — a hand-written numeric bank id silently drifts when a line is added above it. (b) MANDATORY: wrap the published index in `content.behavior.hud_row_index_clamp`. `ETb.GetStringFromTable` bounds the row above but has NO lower bound, so a negative floor index (off-mesh / no floor) indexes `tableText[-n]` and throws; the slot must also be <8. (c) Prefer `B_BGIFLOOR` alone and drop `B_BGIID` from the design — triangle id changes within one surface and would fire a caption edge on every triangle crossing; floor index is the stable unit. Also gate the caption behind an opt-in `field.toml` accessibility flag and give it a cooldown/min-hold, since a `Wait(1)` edge detector on a boundary-straddling player will flicker the window.

**Opcodes.** `B_BGIFLOOR`, `B_BGIID`, `0x66 SetTextVariable`, `0x20 WindowAsync`, `0xC5 RunSoundCode`, `0x22 Wait`

Nothing here needs a DLL patch — 0x66/0x20/0x22 plus a pure expression is the stock minigame-HUD substrate (studies/minigame-ui/SURVEY.md §1). Live update is supported in principle: the kit's own clamp rationale states an unclamped negative throws "once per rendered frame", i.e. the `[TEXT=]` replace path is re-resolved on the redraw that `Dialog.Update -> UpdateMessageValue` drives.

But three of the pitch's own "fixes" are wrong or misaimed, and one real blocker is missing.

(1) Fix (b) is not a fix — the clamp is ALREADY unconditional and author-invisible; `compile()` wraps the row itself so an unclamped publish is unrepresentable. Restating it as MANDATORY adds nothing. Worse, on this particular channel the clamp converts a crash into a silent lie: off-mesh / no-floor clamps to 0 and renders row 0's caption, which for an orientation aid is the one wrong answer that matters.

(2) THE ACTUAL BLOCKER, unmentioned: the width bake. `Dialog.AutomaticSize` bakes a strip's width ONCE at open and a later value change never resizes it (journalfield.py:493 and docs/BEHAVIOR.md). The open pass writes the numeric max-width sentinel `10**digits-1` to EVERY slot unconditionally — `behavior.py:3062`, pinned by `tests/test_behavior_hud_expr.py:403` — with no `clamp_slots` awareness. On a `[TEXT=]` slot that sentinel is a ROW INDEX: digits=2 publishes row 99, which fails `tableIndex < tableText.Length` and returns `String.Empty`, so the strip bakes its width over a BLANK caption and every real caption afterwards clips or wraps. The caption channel as pitched ships visibly broken on first open. Fixing it is an emitter change (publish the widest row's index at open for table slots), not a DLL change — but the pitch claims "no new anything", and this is new.

(3) Fix (c) discards the only granularity the use case needs. FF9 floors are disjoint-vertex groups with their own org/flags, and a walker changes floor only across a seam edge (scene/bgi.py:532; docs/WALKMESH_EDITING.md:9-26). A floor is an ELEVATION LEVEL, not a material patch. So the pitch's "reads a number the engine already computes, no new anything" is true only for the elevation tell, and false for the surface-material caption that the pitch leads with.

## 2. Take Me To The Exit

**Status:** KILLED (screen) · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** A one-press assist that walks the player to the field's exit for you — the accessibility answer to long traversal for players who cannot hold a stick continuously, and incidentally a backtracking QoL button. The engine ships the primitive; nothing in FF9 modding has ever called it.

**Mechanism (as proposed).** `0xA4 CalculateExitPosition()` and `0xA0 WalkToExit()` are both zero-argument and emitted by nothing in the package (census: 0 hits each). The body is a tag-3 press receiver (≥9 bytes, per the `IsActuallyTalkable` poll rule) or a SELECT-poller in the ticker reading `const4(0x0001) B_KEY`: `DisableMove (0x2D)` → `CalculateExitPosition` → `WalkToExit` → `EnableMove (0x2E)`. `DisableMove` first is mandatory — the scripted-walk lane and player input both write `curPos` in the same frame and SUM (the falsified PathTo finding). Bail-out: poll `const4(0x0008) B_KEY` (Start held) each tick and `StopAnimation (0x42)` + `EnableMove`. A per-field opt-out is one `Global.Bit` in the ≥8712 band. Verbatim-first: decode what stock does around `0xA0` before trusting the pair, since neither has an in-repo bench.

**Mechanism (screen correction).** Build it as a route-walker on the kit's existing pieces, not on 0xA4/0xA0 as a generic pair. A new `[assist] to_exit` block: (a) at build time enumerate the field's gateway regions, take each one's q0->q1 midpoint as a named destination, and run the existing A*+string-pull router (`ff9mapkit/ff9mapkit/content/pathfind.py`) from a coarse grid of walkmesh cells to each destination, emitting the legs as a table indexed via the 0xD3 computed-index lane so one body serves every start cell; (b) the runtime body is a SELECT poller in the ticker that, on press, calls ExitField (0x9E) for the stock race-free control kill, walks the player leg-by-leg with ordinary scripted Walk/PathTo (nearest-cell lookup -> leg list), then steps into the gateway region and lets the field's OWN existing 0xA4/0x9E/0xA0/Field body finish the door transition verbatim -- so the exit handoff stays byte-identical to stock instead of being re-derived. Bail-out: poll Start each tick, stop the leg loop, and restore control the way `entrylock.py` grants it rather than a bare 0x2E. Opt-out per field via one GLOB bit in the >=8712 band. Budget-check the leg table against EB_FILE_BUDGET; coarse grid or cap the destination count if it blows.

**Opcodes.** `0xA0 WalkToExit`, `0xA4 CalculateExitPosition`, `0x2D DisableMove`, `0x2E EnableMove`, `0x42 StopAnimation`, `B_KEY`

**Novelty claim.** None
