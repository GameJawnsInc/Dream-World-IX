## 1. The .ebo Relocatable Object + Linker

**Status:** SURVIVED · **Effort:** large · **Engine:** stock · **Round:** 1

**Pitch.** A stable ABI for reusable `.eb` "gems": compile a gadget once into a relocatable blob with an explicit symbol/relocation table, then link it into ANY field (novel or verbatim fork) without re-running the content module. Turns the kit's content/ modules from emitters into a library.

**Mechanism (as proposed).** `eventscan.REF_OPS` (eventscan.py:552-563) is ALREADY a complete relocation table — it names, per opcode, which operand index holds a SLOT INDEX (0x07 InitCode / 0x08 InitRegion / 0x09 InitObject operand 0, 0x43 RunSharedScript operand 0) and which holds a UID (0x10/0x12/0x14 operand 1, plus the 0x24/0x39/0x3A/0x4C/0x51/0x87/0x8A/0x8F/0x95/0x96/0x9F/0xA9/0xAD/0xB5/0xBB-0xBF/0xC2 set). Nothing in the repo consumes it AS a relocation table. An `.ebo` = {entry bodies, loc byte, reloc list}. Four relocation classes, all mechanical: (1) SLOT — patch the u8 at a recorded operand offset to the slot `append_entry` actually assigned; (2) UID — same, honoring `eventscan.resolve_uid`'s convention that an object's uid DEFAULTS to its entry index (so slot and uid relocate together, and 250/251-254/255 are absolute, never relocated); (3) FLAG — the `0xC4`/`0xC5` variable tokens inside expression blobs carry a 1- or 2-byte index; record each token's byte offset + width and repoint it at a bit the host field's `flags.py` allocator hands out (long-index form forced so a short index can't fail to widen at link time); (4) TXID — operand 2 of 0x1F/0x20/0x95/0x96, repointed into the host's minted text block. Jumps need NO relocation: `labelasm` resolves them entry-relative and `grow_entry_table`'s docstring already proves func `fpos` is entry-relative. Link = `edit.append_entry(loc=N)` per body + apply relocs, which is the exact in-game-proven splice path `logic-add` uses. Linker refuses on flag-band or uid collision instead of silently disposing a uid holder.

**Mechanism (screen correction).** Reframe as "serialize + link what object.py already relocates", not "nobody uses REF_OPS as a reloc table". Build the .ebo emitter/linker ON TOP of remap_entry_refs/shift_slot_refs (reuse _arg_byte_offset + the argsize==1 guard + expr_obj_uid_offsets), so slot/uid relocation is the proven code path rather than a reimplementation. Fix the two class definitions: FLAG relocs are 0xC0|src|(type<<2) variable tokens found by walking expression blobs with exprsem (record byte offset, index width, AND source Global vs Map — a Map-scoped gem relocated into a Global bit is a save-corrupter); force the long-index form at COMPILE time so link never has to widen. TXID relocs must use dialogue.WINDOW_OPS (0x1F/0x20 -> operand 2, 0x95/0x96 -> operand 3) and handle a 2-byte operand, which the existing same-length 1-byte patcher cannot — either patch u16 in place (fine, same length) or route through logic_edit's txid kind, which already exists. Also state the file-budget interaction explicitly: link is append_entry, so the linker must call eb_budget_used()/EB_FILE_BUDGET and refuse rather than escalate (THE ESCALATION LAW — an over-budget or unknown-opcode emission is a silent no-op on stock Memoria). Gate the whole thing with an eb-src byte-exactness test: link a gem into a field, then assert the linked bytes equal the bytes the existing content module emits for the same gem on that field — a differential oracle you already have for free.

**Sharpened version.** THE .ebo RELOCATABLE GEM — scoped to the parameterized synthesizers, with the encoding rule inverted.

WHAT IT IS. An `.ebo` is (a) one entry body, (b) a Main_Init ARMING STANZA, (c) a reloc table. Both (a) and (b) are link sites; the pitch's "link is append_entry" is wrong and must be dropped. Position-independence of (a) is already guaranteed by the engine: all three jumps are instruction-relative (`target = instr.end + offset`, eb/edit.py:619), so no code reloc is needed inside a body — only operand reloc.

SCOPE, stated up front. Gems are limited to modules whose entry bytes are a pure function of their parameters: chest, savepoint, encounter, music, sps_trigger, gateway, onentry, ate. EXCLUDED and named as excluded: npc.py, player.py, textcarry — these clone or graft the HOST field's own player entry, so their bytes are a function of the host and are not relocatable in principle. A census of which content/ modules are host-derived is rung 0, before any emitter is written.

RELOC CLASSES (five, not three; widths from disasm.argsize, never assumed):
  slot/uid  — 1 byte. Emit with a placeholder index, link via the PROVEN path: object.remap_entry_refs for the seated entry plus expr_obj_uid_offsets for op78 sibling reads. Surface = eventscan.REF_OPS (0x07/0x08/0x09 slot+uid, 0x10/0x12/0x14 uid+tag, 0x43 slot, and the uid@0 of 0x95/0x96).
  flag      — the 0xC0|src|(type<<2) var token, found by walking expression blobs with exprsem. Record byte offset, index width, AND source (Global vs Map — a Map gem relocated into a Global bit is a save-corrupter).
  txid      — 2 bytes (0x1F/0x20 operand 2, 0x95/0x96 operand 3). Patch u16 in place, or route through logic_edit's existing txid kind. Note 0x95/0x96 need BOTH a uid and a txid reloc.
  field id  — 0x2B operand 0, 2 bytes. Required by any gateway/worldexit gem.
  sps id    — 0xB3 operand 2, 2 bytes, per-scene.

ENCODING RULE, INVERTED. Do NOT force the long-index form. I proved it does not survive the kit's own round trip: pretty_expr + exprasm.assemble narrows e40c007f -> c40c7f, so eb-src / cmdasm / _flag_rewidth silently rewrite a forced-long gem a byte shorter. And region._push_var (the emitter behind every content module) picks minimal width, so a forced-long gem is off by one byte per token against module output. Instead: emit NATURAL width, and when a link crosses the 0xFF boundary use the existing, already-tested logic_edit._flag_rewidth (logic_edit.py:201 — cmdasm reassembly with jump relocation). The width problem is already solved in-tree; do not reimplement it.

FORK SEATING. Link into a verbatim fork does NOT append: seat_entry(reserve_party_band=True) -> insert_entry_before_band, an 8-byte slot-record insert that shifts every body and runs shift_slot_refs(+1) across the whole file. The linker must relocate the HOST as well as the gem, and must budget-check the post-insert file, not the pre-insert one.

ARMING IS PART OF THE ABI. The stanza carries its own policy: plain edit.activate (Wait-filler overwrite), activate_block with after_player=True (the player-handshake ordering that ExitField depends on), or a region.guarded_call story gate (the OBJECT-INIT GATE LAW). A gem that ships only a body throws away the hardest-won part of each module.

BUDGET. Already free — eb/edit.py:119 raises on EB_FILE_BUDGET and EB_ENTRY_SIZE_MAX. The linker adds only one thing: it must re-check AFTER the arming insert and after a band insert, since both grow the file downstream of append_entry's check. Never escalate; refuse (THE ESCALATION LAW).

THE GATE, honestly framed. The `linked == module-emitted` differential is a REGRESSION harness for the emitter, not proof of value: wherever it runs, the module runs too. Its real job is to prove the .ebo emitter is faithful on the in-scope synthesizers — and with natural-width encoding it can actually be green, which under the original forced-long rule it could not. The value case (a gem linked into a field no module was written for) is unoracled and needs a playtest, per the project's own rule that a green gate is a regression harness, not an oracle.

## 2. The Budget Linker Map

## 10. An IR With A Register Allocator

**Pitch.** The research-arc swing: put a real compiler middle-end between the content modules and the bytes, so story flags and per-object locals become ALLOCATED registers with liveness, not a monotonically growing squat on a 2048-byte array.
