## 1. The 26-Bit Overflow Prover

**Status:** SURVIVED · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** exprsem already walks every RPN stream for arity and balance; teach it to carry an INTERVAL per stack slot and it can statically prove no intermediate ever leaves the ±2^25 envelope. The one silent-wrong-answer class in the whole computational lane becomes a build error.

**Mechanism (as proposed).** Extend `eb/exprsem.py` `analyze()` from a depth counter to an abstract-interpretation pass over intervals. Every push token has a known range from its own encoding, not from a cast (there is no cast operator in the shipping engine): `Global.Bit[n]`->(0,1), `.Byte`->(0,255), `.SByte`->(-128,127), `.Int16`->(∓32768), `.UInt16`->(0,65535), `.Int24/.UInt24`->(∓8388608) (both share one engine case and sign-extend), `const(N)`/`const4(N)`->exact, `B_SYSVAR[20]`->(0,8388607) engine-clamped, `B_SYSVAR[0]`->(0,255), `B_SYSVAR[19]`->(0,95). Operators compose intervals the obvious way (B_MULT multiplies the four corner products, B_SHIFT_LEFT scales, B_PLUS adds); a `B_VECTOR` read is unbounded unless the author declares a range on that vector id. Any node whose interval escapes EXPR_VALUE_MIN/MAX (`eb/opcodes.py:543-552`) raises with the offending subexpression printed. Bonus lvalue check: a `B_LET` into `Global.Byte[n]` whose rhs interval exceeds 255 is a wraparound bug the same pass catches for free. Ship it wired into `lint-eb` and `behavior lint` so it is enforced at the call site, not a docstring.

## 2. The Lehmer Seed Box

**Status:** SURVIVED · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** A deterministic, save-persisted, reseedable PRNG in pure RPN — so 'random' content becomes reproducible, shareable and testable, which B_SYSVAR[0] can never be because it is IMPURE and shares the engine's global stream.

**Mechanism (as proposed).** One vector cell holds the state. The recurrence is a Lehmer generator chosen specifically to fit the 26-bit envelope: `x' = (75 * x) % 65537`, max intermediate 65536*75 = 4,915,200, comfortably inside ±33,554,431. RPN for one draw: `{ <tid> const(0) B_VECTOR  <tid> const(0) B_VECTOR const(75) B_MULT const(65537) B_REM  B_LET B_EXPR_END }` (the vector cell is a resolvable lvalue, so B_LET writes it), then derive a bounded roll with `... const(N) B_REM`. Seeding: `Menu(1,char)` is unavailable as a readable input, so seed from the shipped `[[numeric_input]]` stepper (a player-typed run code), or from `B_SYSVAR[20]` play-time seconds for a 'random but recorded' run, writing the seed into cell 0 and a copy into cell 1 so the run code is displayable later via SetTextVariable. Because the state is in gScriptVector it is save-serialized, so a draw sequence survives save/load and a reload cannot reroll a bad result — the opposite of B_SYSVAR[0].

**Mechanism (screen correction).** One real defect: the pitch says the state "is in gScriptVector so it is save-serialized" and survives reload — but the kit's own table lane REBUILDS its tables at every field entry (`content/behaviortoml.py:37,447` "re-seeded every field entry"; `content/behavior.py:1007-1009`, and `Main_Init` emits `B_VECTOR_SIZE const(0) B_LET` then re-writes every cell at `behavior.py:2444-2452`). A seed cell allocated in the ordinary auto-allocated band (`TABLE_ID_BASE = 1000`) would be zeroed on every re-entry, so the stream restarts, not persists. The seed box therefore needs a table id explicitly OUTSIDE the kit's re-seed lane (a declared persistent table whose Main_Init seeding is conditional on "cell == 0", i.e. seed-once-if-unset), or the state mirrored into a GLOB word in the >=8712 safe band and re-loaded into the cell at entry. Also constrain the seed: reduce it mod 65537 and reject 0 (a 0 state is a fixed point of `x' = 75x mod 65537` and yields a constant stream), and note the `65537 % N` modulo bias when deriving a small bounded roll with `const(N) B_REM`.

## 5. const4-Packed Table Unpacker

**Status:** KILLED (verify) · **Effort:** medium · **Engine:** stock · **Round:** 1

**Pitch.** Seeding a vector cell-by-cell costs ~12 bytes of .eb per entry, which is why table-shaped content still eats the 64KB budget. Pack 8 entries into one const4 literal and unpack them in a 5-instruction loop: an ~8x compression ratio on every data table the kit emits.

**Mechanism (as proposed).** The `B_CONST4` token is 0x7E + 4 raw bytes and the engine masks its read to 26 bits, so one token carries 26 usable bits = 8 three-bit fields, or 3 eight-bit fields, or 2 twelve-bit fields. Compiler side: bin-pack each declared table into const4 words. Runtime side, one loop body per word, index `i` in a Global.Byte scratch: `{ <tid> Global.Byte[i] B_VECTOR   const4(<packed>) const(3) Global.Byte[i] B_MULT B_SHIFT_RIGHT const(7) B_AND   B_LET B_EXPR_END }` — note the shift amount is itself a computed subexpression, which the RPN machine allows anywhere. Then `Global.Byte[i] B_POST_PLUS`, compare, JMP_IFNOT back. Cost: ~40 bytes of loop plus 5 bytes per 8 entries, versus ~96 bytes for 8 unrolled seed statements. This is the honest, measurable relief lever for the §1 budget that the constraints brief asks for BEFORE proposing engine work, and it composes with every existing vector table in `content/behavior.py`.

## 10. Offline World Simulation Ticks

**Status:** SURVIVED · **Effort:** research-arc · **Engine:** stock · **Round:** 1

**Pitch.** Every NPC in the world keeps moving while you are somewhere else. Compile an all-pairs next-hop routing table at author time, store each wanderer's position and destination in the save, and advance every one of them by elapsed play-time on each field load.

**Mechanism (as proposed).** Author-time (Python, where real pathfinding is legal and cheap — the engine-side geometry lane is a proven dead end, so none of it happens in .eb): build a node graph of rooms/fields and emit a next-hop matrix packed into one vector, `route[cur*N + dest]`, via the const4 packer. Runtime: per agent, three cells (`at`, `goal`, `progress`). On Main_Init of ANY field, compute `dt = B_SYSVAR[20] - last_tick` (both small, safely inside the envelope), `steps = dt / <secs_per_step>` via B_DIV, then loop steps (capped at a small constant so a long absence does not blow the per-tick iteration budget) doing `at <- route[at*N + goal]` — a single computed-index vector read per step, which is exactly what 0xD3 was for. Presence is then a pure query: an NPC's InitObject call site in any field gates on `{ <at_tid> const(<agent>) B_VECTOR const(<thisfield>) B_EQ }` (gate the CALL SITE, never return early from an Init before SetModel). Result: a courier who is genuinely somewhere, a merchant caravan you can intercept, a rival adventurer racing you for a chest that idea 4's dictionary ledger says is still unopened. Everything the player sees is an ordinary object shown or hidden; the simulation is arithmetic over save data, so it costs no movers and cannot trip the O(n^2) WalkMesh.Collision wall.
