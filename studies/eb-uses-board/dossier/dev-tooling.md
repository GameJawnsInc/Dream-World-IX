## 1. The `[[assert]]` block — assertions that run in the field

**Status:** SURVIVED · **Effort:** medium · **Engine:** stock · **Round:** 1

**Pitch.** A declarative assertion library that compiles to `.eb` and writes machine-readable verdicts into a reserved GLOB band, so a playtest produces a pass/fail vector instead of a human's impression. The key trick is the RAN bit paired with the PASS bit — the only thing that distinguishes "asserted and passed" from "the assertion never executed", which is exactly the failure mode a green gate suite cannot see.

**Mechanism (as proposed).** Each `[[assert]]` clause is an RPN predicate assembled by `eb/exprasm.py` (any READ tokens: `Global.Bit[n]` 0xC4, `B_SYSVAR[6]` gil, `B_CURHP`, `B_BGIFLOOR`, `obj(uid=U).f[F]`, `B_HAVE_ITEM`). The compiler emits, into a seated tag-1 entry, per assertion i: `0x05 SET(Global.Bit[ASSERT_RAN+i] const(1) B_LET)` then `0x05 SET(<pred>)` / `0x02 JMP_IFNOT +k` / `0x05 SET(Global.Bit[ASSERT_PASS+i] const(1) B_LET)`. Cost ≈ 20-30 bytes per assertion, well inside the §1 budget. Readback has two lanes and needs neither new engine surface: (a) `tools/harness/session.py:2582 watch(bit)` already publishes arbitrary `gEventGlobal` bits and `channel.State.flag(bit)` reads them, so a scenario asserts in Python against verdicts the field computed; (b) with no harness, a `WindowAsync` whose text is `[TBLE=bank]` indexed by `SetTextVariable(0, <first failing index expr>)` renders the failing assertion's NAME on screen for `tools/game_snap.ps1`. Band: a named allocation out of `flags.py` [8712,16320), e.g. ASSERT_RAN/ASSERT_PASS as two 64-bit windows, registered like `AUTO_CUTSCENE_BASE`. `exprsem.analyze()` refuses an underflowing or unbalanced predicate at build time, and `UNSAFE_TO_REPEAT` must reject `B_SYSVAR[0]`/`B_SYSVAR[9]`/`B_PARTYADD` inside an assertion since the loop re-evaluates it every tick.

**Mechanism (screen correction).** Three fixes, none structural. (1) "0x22 Wait" is wrong — OP_NAMES has no 0x22; the wait family is 0x41 WaitAnimation / 0x54 WaitWindow / 0x50 WaitTurn. Drop Wait from the opcode list or resolve the real idle opcode from `_optables.py` before emitting a polling loop. (2) The token is not a fixed literal 0xC4 — write it as the `Global.Bit[n]` source token and let `exprasm.py:108-123` encode it, since every assertion index is >=8712 and therefore takes the `| 0x20` long-index encoding, which a hardcoded 0xC4+1-byte index would silently truncate. (3) Prefer a once-per-entry evaluation seated in the tag-1 body over a per-tick loop: UNSAFE_TO_REPEAT protects you from impure reads but not from the `.eb` byte budget or from an assertion that re-latches PASS after the condition has already regressed. If a tick loop is wanted, add a STUCK bit (pass-then-fail) as a third window, or the RAN/PASS pair still cannot distinguish "passed once early" from "held true".

**Opcodes.** `0x05 SET`, `0x02 JMP_IFNOT`, `0x22 Wait`, `0x66 SetTextVariable`, `0x20 WindowAsync`, `0xC4 Global.Bit token`, `B_LET`

3. BAKE THE BUDGET IN AT THE CALL SITE. 9 bytes per verdict write, ~25-40 per assert, against `EB_FILE_BUDGET = 0xFFFF` — so the linter should report bytes-spent per field, not warn abstractly. Route every `Global.Bit[n]` through `exprasm.assemble` and never a literal `0xC4`: at n>=8712 the encoder emits `0xE4` + 2-byte index, and a hardcoded token truncates silently.

4. PREFER TAG-1 ONCE-PER-ENTRY. If a tick loop is genuinely needed, the back-edge must be `0x01 JMP` — `0x02 JMP_IFNOT` reads its offset unsigned and labelasm refuses a backward target — and the triple must be RAN/PASS/STUCK, since RAN+PASS alone cannot separate "passed once early" from "held true".

The honest scope claim, which the pitch should state rather than imply: this buys coverage of *field-script state transitions* (a flag latched, a chest consumed, a gateway reached, a behavior-tree node fired) on fields the harness can drive but where `state.json` exposes no hook. Build it only if a named, currently-unanswerable question exists; otherwise the cheapest move is to add a `check` to the harness scenario and mint no surface at all.

## 2. Debug LEDs: Bubble + HereIcon as two always-on bits

**Status:** KILLED (verify) · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** Bind any boolean expression to the "!" bubble (0x68) and the location marker (0xEF) in a tick loop — two zero-art, zero-window status lamps that are legible in a `game_snap.ps1` PNG without interrupting play. ## 6. Breadcrumbs and the watchdog object

**Pitch.** Stamp a one-statement breadcrumb at the head of every function body, and run a separate seated object whose only job is to display the last breadcrumb.
