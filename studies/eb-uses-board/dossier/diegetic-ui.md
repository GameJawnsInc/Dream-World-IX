## 1. The Pinned Pane Reader

**Status:** SURVIVED · **Effort:** medium · **Engine:** stock · **Round:** 1

**Pitch.** A general multi-pane list/document viewer that lives inside a field: header, scrollable body, footer, all rendered as pinned dialogue windows with runtime-indexed text rows. FF9 has exactly one text surface — one bubble at a time — and this turns it into a terminal.

**Mechanism (as proposed).** Layout: each pane is its own .mes entry carrying [MPOS=x,y] (content/text.py:141 — the absolute-pin tag; a pinned window draws no tail, which is what makes it read as a panel and not a bubble). Open with WindowAsync (0x20) on distinct ids (header=0, body=1, footer=2 — ids 0-7, never 255, depth 68-2*id), RaiseWindows (0x8E) ONCE per open. Body rows: the entry is six lines of [TEXT=bank,slot] with slot=0..5; a tag-1 daemon publishes SetTextVariable(slot, <cursor+slot>) via 0x66 with arg_flags=0b10 (expression form, escapes the ±32767 immediate). Scroll: the daemon polls B_KEY/B_KEY2 in an expression, does cursor += 1 / -= 1 into a MAP or GLOB var, then re-issues WindowAsync on id 1 — re-issuing a live id REPLACES that window (ETb.cs:96, eb/opcodes.py:395), which is the repaint primitive. CRITICAL: use WindowAsync not WindowSync — a WindowSync parks the object at gCur.wait=254 and the interpreter skips it entirely, so it can never poll. Every row index goes through the non-negative clamp `E E const(0) B_GE B_MULT` (content/behavior.py:771) or a negative cursor throws in ETb.GetStringFromTable. Banks may exceed 255 safely (texttable.py's WDTH analysis) so a long document is many banks.

**Mechanism (screen correction).** Two fixes, both from laws already in the repo. (1) THE RAISE-SATURATION LAW (`eb/opcodes.py:429-442`): the raise is clamped at 68+22=90, so window 0 saturates after ONE raise while window 7 climbs 54→76→98 and the id order INVERTS on the third raise. The pitch says "RaiseWindows ONCE per open", which is right for the initial three opens, but a scroll repaint re-issues window id 1 and must NOT emit a bare re-raise of the unchanged stack — otherwise the body pane climbs past the header/footer and z-order flips mid-scroll. Emit raise only on the initial opens; the repaint is WindowAsync alone. Also note stock's own multi-window UI (the Treno keypad) never raises at all — raise is only needed inside a FadeFilter bracket, so most panes need zero raises. (2) CloseWindow on a [PAGE]-split entry turns the page instead of closing (`eb/opcodes.py:402-410`), so pane entries must be single-page, or teardown needs one close per remaining page.

## 2. The Live Field Inspector

**Status:** KILLED (verify) · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** A corner overlay the game draws about itself: walkmesh triangle id, floor index, frame counter, playtime, party gil, usercontrol — live, every tick. It exists so the agent can read the game's own state out of a screenshot instead of guessing.

**Mechanism (as proposed).** One seated tag-0 entry, ticker-shaped (the content/gauge.py daemon shape: single function, internal Wait(1) loop, armed by InitCode 0x07). Per tick it writes SetTextVariable(0, B_BGIID), (1, B_BGIFLOOR), (2, B_FRAME), (3, B_SYSVAR[20]), (4, B_SYSVAR[6]) — all 0x66 with arg_flags=0b10 — then re-issues WindowAsync(7, flags, <txid>) on a [MPOS]-pinned entry whose body is `TRI [TEXT=lbl,0] FLR [TEXT=lbl,1] F [TEXT=lbl,2]`. B_BGIID/B_BGIFLOOR are the walkmesh triangle and floor under the actor — the ONLY spatial classifier that actually works in .eb, and the kit references neither. Toggle: a B_KEY2 chord flips a GLOB bit; the daemon JMP_IFNOTs the whole publish block when clear, so it costs ~nothing when off. Refresh cadence should be Wait(6), not Wait(1) — a per-tick window re-issue is a per-tick allocation and the panel only needs ~3 Hz to be readable in a game_snap PNG.

**Mechanism (screen correction).** Three fixes. (1) B_BGIID/B_BGIFLOOR have ARITY 1 (exprsem.py:162-163), like B_CURHP — they are not bare terminals; emit them as `<actor-uid> B_BGIID` so the read is per-object (player uid for the player's triangle). (2) Note the CalcStack ceiling: opcodes.py:542-552 — a COMPUTED SetTextVariable value is 26-bit signed pushed through expr_Push_v0_Int24, and only a BARE terminal var bypasses the push for a full Int32. Keep each slot a single terminal read (no arithmetic on B_FRAME) or the high bits collide with the VariableSource tag. Also HUD_DIGITS_REACHABLE=5 (65535) is the widest renderable value, so B_FRAME must be shown modulo or as a low-order tick, not raw.
