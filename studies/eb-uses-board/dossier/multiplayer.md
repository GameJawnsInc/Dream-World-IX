## 1. Ghost Runner Recorder

**Status:** SURVIVED · **Effort:** large · **Engine:** stock · **Round:** 1

**Pitch.** Record the local player's route into a save-persisted gScriptVector, then replay it as a translucent actor so a friend races your ghost — Time Trial in a pre-rendered field, with the ghost travelling in the save file.

**Mechanism (as proposed).** A looping CODE entry (the stolen-ember watchdog idiom: assign, Wait(1), jump back) samples the player every N ticks and APPENDS two cells: `const(tidX) B_VECTOR_SIZE <x> B_LET` style writes at index==size (the append rule behavior.py already exercises at :2444-2452 and :2893). Decimate with a tick counter, not B_FRAME, so the sample rate is authored. Playback: a second entry walks a cursor index and drives a cloned actor with `WalkXZY 0xA2` (or `MoveInstantXZY 0xA1` for a stutter-free ghost — note the (x, −y, z) sign trap), `SetWalkSpeed 0x26`, `SetModelColor 0x8F` for the translucent tint, `EnableShadow`/`DisableShadow 0x7F/0x80` off. Coordinates are Int16-sized so every computed intermediate stays well inside the 26-bit envelope. One extra mover only — the WalkMesh.Collision O(n²) wall is about movers, and one ghost is cheap. Transport: `save.py:extra_file_path` + `read/patch_extra_gEventGlobal` already round-trip the Memoria extra save, so a `ghost export/import` verb mirrors the route band between two players' saves. Budget note: sample stride is the lever — a 2,000-cell route is 2 vector ids, not .eb bytes, so it costs nothing against EB_FILE_BUDGET.

**Mechanism (screen correction).** Two mechanism fixes. (1) Translucency: 0x8F SetModelColor is an RGB tint, not an alpha channel — there is no per-model transparency opcode in the table (0xED SetTileLoopAlpha is tile-layer, not model). Author the ghost as a tinted/darkened solid with DisableShadow, or accept an opaque ghost; do not promise translucency. (2) Append: writing at index==size does not itself grow the vector — the kit's own pattern sets B_VECTOR_SIZE explicitly (behavior.py:2444-2445) before writing cells, so a recorder must do `tid B_VECTOR_SIZE (tid B_VECTOR_SIZE + 1) B_LET` and then write the new tail cell each sample. (3) Because the vector id namespace is save-GLOBAL and every kit table re-seeds from TABLE_ID_BASE=1000 at Main_Init, a persisted route band must be allocated OUTSIDE the kit's auto-allocation band and explicitly excluded from the re-seed, or the first behavior-bearing field entered will zero it.

STILL HAND-WAVED (corrections, not kills):
1. THE NAMED REPLAY OPCODES ARE THE WRONG ONES. 0xA1/0xA2 act on gExec with 16-bit IMMEDIATE operands, and 0xA1's real arg order is (x, -y, z) (opcodes.py:258-265, "verified from source"). 0xA2 WalkXZY BLOCKS until arrival at engine walk speed, so a fixed-cadence sample list replays at the wrong speed unless per-segment speed = dist/dt — and 0x26 is a single BYTE (0-255 quantisation) with no sqrt on the CalcStack. **Sharpened version.** GHOST RUNNER, re-specified on proven substrate:

RECORD: a per-frame ticker entry (Wait(1); 0x22 is one byte, so <=255-frame waits) samples the player mirror the behavior compiler already uses — obj(uid=250).f[0] / .f[2] — and appends two cells: `{R B_VECTOR_SIZE  R B_VECTOR_SIZE const(2) B_ADD  B_LET}`, then two computed-index writes at the new tail. Cap the sample count in the script itself (a hard cell ceiling with a stop branch): nothing else bounds the save's growth. R is a persistent vector id well clear of the 1000+ auto band, and the field must NOT declare it as a [behavior] table — every declared table re-seeds size<-0 at Main_Init and would erase the route. 0x11A ClearMemoriaVector(R) is the explicit "erase my ghost" verb.

REPLAY: inside the ghost object's own entry, per frame, 0xBF MoveInstantEx(ghost_uid, x_expr, z_expr) with both operands expression-flagged blobs reading R[2i] / R[2i+1] — the fort-condor rung-3 spawn-at-feet shape with a different operand, not a new bytecode shape. Teleport-per-frame reproduces the recorded TIMING exactly; walking (0xA2 + 0x26) cannot and re-collides. Drive the run clip explicitly (0x40 RunAnimation), since a script-moved actor otherwise slides in its last pose. 0x80 DisableShadow plus 0x4B SetObjectLogicalSize shrunk toward 0 so the racer can run THROUGH the ghost; a dark SetModelColor tint is the look, with no promise of alpha (no per-model alpha opcode exists).

BENCH BEFORE BELIEVING (one mechanism per playtest): (a) does size<-size+1 preserve cells 0..n-1 in-game, and what does a 2000-cell vector cost per frame and in the extra-save JSON; (b) does a per-frame MoveInstantEx ghost read smooth or jitter against the field's frame pacing. Then ship a save.py gScriptVector extract/inject pair so a ghost exchanges as a small file instead of a whole save, and a lint that refuses a persistent vector id inside any field's auto-allocation band — otherwise the id rule is a wish.

## 2. Message Stones

**Status:** SURVIVED · **Effort:** medium · **Engine:** stock · **Round:** 1

**Pitch.** Dark-Souls notes for FF9 fields: a player composes a short message from authored phrase banks, it is stored in a portable flag band, and another player's save shows it at the exact spot where it was left.
