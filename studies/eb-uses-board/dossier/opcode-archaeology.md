## 1. The Frog Counter As Free Global Int

**Status:** KILLED (verify) · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** `AddFrog()` is the only engine-backed, field-agnostic counter opcode in FF9, and the kit reads it but has never written it. Use it as a save-persistent integer that costs zero story-flag band and renders itself.

**Mechanism (as proposed).** `0xE0 AddFrog()` is 0-arg and increments `Frogs.Number`; the value reads back as `B_SYSVAR[16]` (bounds 0..65535, confirmed at `ff9mapkit/ff9mapkit/journal.py:1298`). So one byte of `.eb` = `counter++` on a save-persistent 16-bit integer that needs no `gEventGlobal` allocation, no long-index token, and no entry in the >=8712 band. Read it in any expression: `B_SYSVAR[16] const(10) B_GE` gates a door at ten kills/collectibles/favors; `B_SYSVAR[16] const(5) B_REM` drives a five-state cycle. There is no decrement opcode, so the idiom is monotonic-only: use it for reputation, a stamp card, a kill tally, an NG+ run count, or a 'how many times have you done this' narrator. Pair with a GLOB byte holding a baseline (`Global.Byte[n] = B_SYSVAR[16]` at chapter start) to get per-chapter deltas out of a monotonic counter. ⚠ One honest footgun: `journalcatalog.py:431` already maps sysvar 16 to the `side.frog-catching` Journal row scored against Frog99, so any field that spends AddFrog for a non-frog purpose lies to the completion Journal. Fix is one line in the catalog (drop or rename the row) or a declared `frog_counter_role` in field.toml.

**Mechanism (screen correction).** Two couplings the pitch misses, both of which make "free global int" false as stated. (1) Frogs.Number is Quina's FROG DROP damage input — the ability scales off the caught-frog count (see battle/battlecsv.py:45 `66: "FrogDrop"`), so any field spending AddFrog for reputation/kills silently buffs a player ability and, at 99, trips the Frog99 achievement (journal.py:77, `40000_Common/frog_no`). (2) Qu's Marsh dialogue tiers off the same count. So the honest framing is not "a free counter" but "a SHARED engine counter with three existing consumers". Corrected mechanism: keep the read-side idiom (B_SYSVAR[16] with B_GE / B_REM) but do NOT write raw AddFrog as a general counter. Either (a) declare it: a `[frog_counter]` / `frog_counter_role` block in field.toml that takes exclusive ownership, emits 0xE0, drops or renames the journalcatalog row, and LINTS an error if the campaign also ships Quina or a Qu's Marsh fork; or (b) use it only in campaigns with no Quina and no frog-catching journal section, i.e. custom standalone worlds. The baseline-delta trick (snapshot into a GLOB byte at chapter start) is sound and worth keeping either way, as is the monotonic-only constraint — there is no decrement opcode, so anything needing a reset must reset via the baseline, not the counter.

## 2. Control Twist As A Status Effect

**Status:** SURVIVED · **Effort:** small · **Engine:** stock · **Round:** 1

**Pitch.** The kit emits `SetControlDirection` once, statically, to fix camera yaw. Drive the same opcode from a per-frame director with a computed operand and it becomes vertigo, a river current, a mirror room, or a curse that gets worse.

**Mechanism (as proposed).** `0x67 SetControlDirection(x:1, y:1)` writes the TWIST control-axis remap; `(-1,-1)` is the verified encoded pair. Both operands are ordinary immediates, so both are expression-capable via `argFlag` (0b01 / 0b10 / 0b11) — nothing about the opcode requires a constant. Seat a director entry (tag 1, `Wait(1)` loop, the same architecture `content/behavior.py` already uses for the central ticker) that re-emits `SetControlDirection(<expr>, <expr>)` each tick with the axis derived from a free clock: `B_FRAME const(64) B_REM` for a slow rotational drift, `B_FRAME B_SIN` for a swaying-deck wobble, or `Global.Byte[curse] const(8) B_MULT` so the twist deepens as a story byte climbs. A hard `const(-1) const(-1)` is a mirror world where left is right. A single-axis flip is a one-way current. Because TWIST sits on the control mapping and not on `usercontrol`, movement stays fully enabled — the player is not locked, just misaimed, which is the thing that makes it a mechanic instead of a cutscene. Exit is one `SetControlDirection(1,1)` and is safe to fire from a gateway's on-exit body, so the state never leaks to the next field.

**Mechanism (screen correction).** Two fixes. (1) B_FRAME is ARITY 1, not a nullary frame counter (exprsem.py:162, DoCalcOperationExt.cs:21-26 — it takes an operand), so `B_FRAME const(64) B_REM` does not assemble as written. Use an explicit tick counter the director owns — a GLOB/gScriptVector byte incremented each Wait(1) pass and B_REM'd — or a B_SYSVAR timer cell; B_SIN then takes that counter as its single argument. (2) The operand is one byte per OP_ARG_SIZE, so the expression result must be reduced to the signed-byte encoding before it is written (mask to 0-255 / reuse movement.control_value_for_angle's normalise-then-wrap); an unmasked expr value will alias. Also emit the restoring SetControlDirection(1,1) as noted, and keep movement.set_control_direction's "exactly one TWIST in Main_Init" precondition intact by seating the per-tick emitter in a separate director entry, not in Main_Init.
