# summary

I judged the three designs, checked the disputed claims against C:\gd\FFIX\Memoria, and merged them into one build-ready design. Nothing was edited, built or deployed.

The build is called F3.2, "host-authoritative dialogue". It ships in three stages with one in-game test each. Stages C1 and C2 keep the wire at v13; only C3 bumps it to v14.

**Scorecard** (1-5, higher is better)

| Criterion | A (minimal) | B (authority) | C (feel) |
|---|---|---|---|
| S-WARP, strictly | 4 | 5 | 5 |
| S-SYNC, strictly | 3 | 5 | 5 |
| Never wedges the guest | 4 | 4 | 5 |
| Vanilla/solo unchanged | 5 | 3 | 4 |
| Risk and size | 5 | 2 | 3 |
| Player feel | 3 | 4 | 5 |
| **Total (/30)** | **24** | **23** | **27** |

Why each design lost points:
- **A, S-WARP (4):** it keeps the usercontrol force-pin. To let a relayed talk's `ifnot(IsMovementEnabled)` prologue pass, it has to hand control back for one event tick.
- **A, S-SYNC (3):** the lock only arms while `_l2Engaged` is set (host flag, provisional, or tail). So a guest that is ahead of the host opens its window unlocked, for example in a field-entry Main_Init scene. The tail also hands windows back to local input.
- **A and B, never wedges (4):** neither detects a hung host. The writer thread keeps re-sending the last state slot (NetSyncSocket.cs:308-312), so the lane stays fresh forever.
- **B, vanilla (3):** it edits the hot path at FieldMapActorController.cs:636-650. Memory flags that file for uncaptured patch drift.
- **B, size (2):** one large v14 build with END events, credits, synthesized presses, (uid, ip) keys and an input-layer pin.
- **C, size (3):** 16-byte FIFO frames plus a ring, seq dedup, a 300 ms gap hold, a typewriter-skip frame, and a four-state window classifier.

**Winner: C.** It is the only design that does all four of these:
- the lock arms from window-open and does not depend on the host's flag;
- every release is driven by host state, never by guest input;
- it detects a hung host (heartbeat);
- it deletes the L1 control force-pin, which is the actual root of TALK-3, instead of working around it.

**Grafted onto C:**
- From A:
  - the staged rollout with a no-wire middle stage;
  - the two VoicePlayer seams;
  - the host tap gates;
  - the quad-deferral state machine;
  - the scene-fall rule "host control back for at least SceneFallMs". A rule based on windows closing would never fall on a field with a persistent [NFOC] HUD strip.
- From A's C3 and from B: the dialogue ring in the latest-slot state section as the only delivery channel. C's FIFO+ring is unnecessary because the slot is re-sent every 33 ms (NetSyncSocket.cs:312) and pushed out-of-band on every change.
- From B:
  - a new NetSyncDialog.cs, so NetSyncClient.cs only gains hooks;
  - per-dialog lock checks at the choice seams;
  - the KEY ordering guard;
  - an `_enabled` conjunct on every static gate. `_role` defaults to "selftest" (NetSyncClient.cs:71), and `_instance` survives a disable (:363-374).

**Rejected:**
- B's input-layer pin. It becomes an owner option instead.
- B's poll keys built from the script ip:
  - the ip is mid-expression when B_KEYON is read;
  - the .eb differs per language;
  - gCur is not the executing object for STARTSEQ scripts (EBin.cs:159, :164-165, :181).
- B's synthesized presses and credits.
- A's tail, provisional engage, and one-tick control hand-back.
- C's typewriter-skip frame (moved to suggestions).

**The build**
- **C1 (v13):**
  - Deletes all three automatic SnapToHost calls and the L1 control force-pin.
  - The talk relay now defers instead of silently failing, and consumes the nonce only when the start is accepted.
  - A press-region start is relayed only once the host's handler opens a window.
- **C2 (v13):**
  - The host's scene flag becomes sticky, with one nonce per scene.
  - Every lockable ETb window on a following guest is locked from the frame it opens, at every input seam: keys/pad/turbo, mouse and touchpad click, drag, cursor select, and voice auto-dismiss.
  - Host frames apply per window key.
  - Nothing is drained, and the 8 s "local advance restored" timeout is deleted.
  - A window is released only when:
    - the host provably lacks it (it is then auto-closed at reading pace);
    - the link is dead for 3 s;
    - the session ends;
    - the player uses a ~ menu panic button.
- **C3 (v14):**
  - Delivery moves into a 32-event ring in new state section 7, which also carries an epoch, a host heartbeat, host flags and the host's open windows.
  - Relays the host's script button polls, so the save moogle, shops, [NFOC] pages and "press Confirm" beats follow the host.
  - Mirrors the host's choice cursor.
  - Releases the lock on a hung host.

**Verified facts the design rests on**
- **Request has no distance gate** (EventEngine.cs:339-349).
- **A usercontrol pin defeats the relayed talk.** Every stock _SpeakBTN opens with `ifnot(IsMovementEnabled) return`, and sysvar 2 is usercontrol (GetSysvar.cs:17-18).
- **Only one input path honours the guard.** UIKeyTrigger.cs:829 is the only gameplay reader of SuppressLocalDialogInput. DialogManager.OnClick (:310-319) bypasses it.
- **The old lock arms late and lets go on its own.** Suppress is set only on a matched frame (NetSyncClient.cs:2027) and released by the 8 s timeout (:2070-2081).
- **Any flag-0 sample drains the queue** (:1931-1934, :1958-1962).
- **The host nonce bumps on every window gap** (:1673-1681), because a WindowSync thread resumes via next0() on a later pass (EBin.cs:136-157).
- **The VA close path runs off the main thread** and reaches the host tap through Dialog.OnKeyConfirm(null) (VoicePlayer.cs:84-108, :234, :273). The ring therefore needs a lock, and the state frame is only pushed from the main thread.

**S5. Guest: tracker, inbox and apply**

**Delivery model**
- The type-5 slot is re-sent every 33 ms write tick (NetSyncSocket.cs:312).
- The host also rebuilds and pushes it out-of-band, on the main thread, on any of:
  - a new ring event;
  - a scene edge;
  - an open-set change (open, close, page or cursor).
- Ring writes happen under `_ringLock` because the voice-acting close arrives off the main thread (VoicePlayer.cs:84-108, :234, :273). A tap only appends and sets a dirty flag.
- The guest copies events into its own inbox the moment it sees them, so the ring only has to span the events between two received state frames.
- A gap is logged; the affected window falls to the orphan rule.
- The scene flag and the events always arrive in one snapshot, so the flag can never overtake or drain a frame.

**Unchanged sections**
- Section 5 keeps `[flag][nonce]` for older readers and logs.
- Section 6 SectionTalk keeps its 5-byte layout, with the host TTL at 4000.
- No change is needed in Python: netsync_bridge.py and the relay forward frames without regard to version.

**Cost**
- About +0.4 KB per state frame, which is about +12 KB/s at the 30 Hz re-send.
- A few out-of-band pushes per line or cursor move.
- For comparison, the existing roughly 90 KB/s of identical state re-sends (WIRE-7) is untouched; send-on-change is listed as a suggestion.

# softlock_escapes

Every locked guest window and every masked guest script poll ends by one of the paths below. Except for the deliberate panic unlock (escape 10), none of them returns input to the guest while a live host that is co-located (or arriving) could still drive that window.

1. **Host event.**
   - ADV, CHO or KEY applies once the guest's matching window or poll exists.
   - It is consumed only if the window actually advanced; otherwise it is retried every tick (DLG-7).
   - From C3, delivery heals itself: the ring rides a latest slot re-sent every 33 ms.
   - A closing ADV keeps paging the window until it closes.
   - No condition ever drains pending events while the lock is on.

2. **The window closes on its own.** None of these is an input seam, so none is blocked:
   - the guest's own script CloseWindow (DialogManager.Close/CloseAll);
   - a [TIME] AutoHide (Dialog.cs:840-870);
   - the voice-close that follows a host-applied voiced choice (VoicePlayer.cs:227/:273).

3. **Orphan (the host provably lacks the window).**
   - Conditions: the host has been settled continuously for OrphanGraceMs 2000, and nothing claims the key. "Settled" means:
     - the sticky scene is down and no talk section is live for this field, and
     - the host is co-located (C3 adds: with no non-[NFOC] line open), OR on another field with no intent pointing here for 5 s, OR off-field with no live battle for 20 s.
   - A confirm window is auto-closed at reading pace, 2 s after it completes:
     - a choice window takes CancelChoice, else DefaultChoice;
     - it closes page by page;
     - one log line per window.
   - An [NFOC]/[TIME]/script-polled window is handed back to local input.
   - Script polls unmask once the host is settled-long and no relayed key is pending.
   - A late host event flips the window back under the host.

4. **Link dead.**
   - When IsLiveFollowedSession has been false for LinkGraceMs 3000 (about 5 s after the last host frame), `_lockEngaged` turns false and every window and poll is local.
   - The baseline is an armed bool plus a subtraction delta, per the tick-baseline law.
   - For a mirrored guest, the existing exit ramp then reloads its own autosave (NetSyncClient.cs:806-857, debounce at :893-899).

5. **Host hung (C3).**
   - The section-7 heartbeat is unchanged for HostStallMs 10000 while the lane is fresh. This catches a frozen host main thread whose writer thread keeps re-sending stale slots (NetSyncSocket.cs:308-312).
   - The lock drops. It re-arms if the heartbeat moves again; windows open at re-arm stay local.

6. **Session or config changes: immediate.**
   - FollowHost=0, a role change, Enabled=0, or a transport reconfigure (ApplyConfigChange → ResetIntentAndL1State → ResetDialogLockstepState, :643-677, :1593-1613).
   - OnDestroy.
   - `_exitRampPending`.
   - Every static gate also requires `_enabled`, because a disabled client keeps `_instance` (:363-374).

7. **The guest leaves the field.** A follow-warp, the same-field kick, a load, or a diorama boot (onField false) destroys the windows. The tracker forgets them, and inbox events for other fields are purged.

8. **Host epoch change (C3, host relaunch).** The inbox and key store are cleared, along with every guest dedup nonce. Windows still open have no events and fall to escape 3.

9. **Pause.**
   - Applies are held while UIManager.IsPause.
   - The guest can always unpause: UIKeyTrigger routes keys through HandleMenuControlKeyPressCustomInput whenever IsPause is set (:640), ahead of the dialog guard (:203).
   - Opening a NEW pause while a locked line is open stays swallowed, as before (finding B).

10. **Deliberate unlock.**
    - The ~ menu button "Co-op: release dialogue lock (this field)", shown only under IsLiveFollowedSession, and the harness verb `netsync unlock` set `_unlockField = fldMapNo`.
    - The lock is off until the next field load.
    - The ~ toggle runs before the dialog guard (UIKeyTrigger.cs:171-179 vs :203), so it is reachable while locked.

11. **No control seizure exists any more.** C1 deletes the L1 SetUserControl(false) pin (:1779-1784), so there is no "restore control" path that could be missed. A relayed talk freezes the guest only through its own copy's DisableMove/EnableMove.

**Invariant.** The only state in which a guest window stays locked indefinitely: the host is live (heartbeat ticking), co-located or arriving, with its sticky scene still up (control still off), or with the key claimed by a pending host event. That is following the host, not a softlock.

# divergence_handling

Events are matched per window key, in host order: (field, winnum, textId). As a result, no divergence can block another window. It shows up only as an unmatched event, which expires, or as an unmatched window, which falls to the orphan rule (softlock escape 3).

**A. The guest's window has a different textId from the host's.**
- Causes:
  - gil, frog or card reads come from the guest's own save (DIO-3; the S. Gate inn, test2_214.txt:532-581);
  - a stale bag mirror (DIO-4; C3 refreshes it at relay accept);
  - pose- or facing-gated handlers, which now evaluate the guest's own position (TALK-4: 263 of 2945 SpeakBTN);
  - RNG chatter (1.2% of windows).
- Handling:
  - The guest's window is locked from open.
  - The host's events for its own key sit pending, block nothing, and expire after 20 s, at a field change, or at the next relayed talk's scene purge.
  - While the host's scene is up, the guest window waits.
  - Once the host is settled for 2 s, the window is auto-closed at reading pace (Cancel, else Default) and the guest's copy continues down its own branch, each further line auto-closing. The guest never presses anything.
  - Durable story consequences are GLOB writes, which the mirror overwrites at the next field load (DIFFICULTY-VERDICT.md:20-26).
  - An owner decision can flip these windows to hand-back instead.

**B. The host's window never opens on the guest.**
- Causes:
  - a stock tag-2 chest or tread scene (never relayed);
  - a quad press whose handler opened no window (not relayed, W4);
  - a relayed start that expired while deferred.
- Handling:
  - With the pin gone, the guest is neither moved nor frozen.
  - Its chip reads "the host is in a scene".
  - The host's events sit pending and expire.

**C. Extra window on the guest.**
- Causes:
  - its own tread cutscene;
  - an ambient window;
  - a scripted Battle() that ran inline (DIO-2).
- The guest can no longer open ATE menus (MISC-08) or the party UI (MISC-07), and it still cannot start talks or quads (EventCollision.cs:74-78, :111-115).
- Handling:
  - Locked from open. A [TIME] window closes itself.
  - While the host's scene is up on this field, the window waits; when the host is settled it auto-closes (rule A).
  - DIO-2 case: the host's sticky scene holds through its battle (onField false = hold), so the guest's early post-battle line stays locked and is driven by the host's Main_Reinit confirm afterwards, unless the diorama boot tears the guest field down first.

**D. Script-polled windows** ([NFOC], [TIME=-1], the moogle's WindowAsync + IsButton + GetDialogChoice, and "press Confirm" beats).
- C2: still driven by the guest's own presses. This is a known C2 gap, because masking without a relay would only freeze them.
- C3:
  - The guest's decision bits are masked whenever its control is off and the host is not settled-long.
  - The host's press arrives as a KEY event for the same reading uid, released only after any earlier host window event for an open guest window has applied (ordering guard).
  - It carries the host's choice cursor, applied before the poll reads GetChoose.
  - It is served to every read by that uid in one key tick.
  - A KEY for a poll the guest never makes expires (1.5 s once both sides are idle; 20 s at most).
  - If the guest's poll never gets a key and the host is settled-long, the poll unmasks to local.

**E. Duplicate-key reopens** (14.2% of sites).
- The per-key FIFO keeps instance order.
- The scene-nonce purge at relay accept drops leftovers from earlier scenes.
- Residual: a stale event from an instance the guest closed by its own script can land on a reopened same-key instance within the TTL (credits are deferred; see risks).

**F. Guest ahead.**
- Causes:
  - its MENU and PARTYMENU opcodes return 0, so it runs on to a shop's farewell;
  - it loaded a field faster than the host.
- The window waits locked:
  - through the host's script menu, because the host's control stays off and the scene holds;
  - while the host is still loading (field 0 or another field with its intent pointing here, which does not count as settled).

**G. Guest behind.**

# risks

- Feel of a strict lock: every unmatched case (divergence, an AFK host mid-scene, a lost frame in C2) holds the guest's line until the host's scene ends, plus 2 s, plus a 2 s read. The chip mitigates this, but only the human can judge it.
- False orphans: if the guest's copy is legitimately ahead while the host has control and no line open (for example the guest walked into a tread cutscene the host will reach 3 s later), the guest's line is auto-closed with the Cancel choice. Requiring the host to be co-located, in control, with no scene and no line, for 2 s narrows this but does not eliminate it.
- Removing the L1 pin lets the guest walk into its own tread triggers while the host is mid-scene. Those guest-only lines are locked until the host is idle and then auto-closed. Previously the pin disabled CollisionRequest entirely (EventEngine.ProcessEvents.cs:186-187).
- The key relay assumes both copies make the same sequence of true polls per reading uid. A divergent branch can consume a press meant for another read; this is bounded by the 1.5 s idle purge, the 20 s TTL and the field/epoch purges. B_KEYOFF stays unmasked (NetSyncField.cs:76-77), so a guest's physical release can still satisfy a rare release-wait.
- Polled-choice correctness depends on the host cursor being applied before the guest's GetChoose read. Applying it when the key is released (before any poll can consume it) avoids depending on B_ANDAND operand order (EBin.cs:847-862), but this is unproven in-game.
- Duplicate-key reopens (14.2%): a stale ADV from an instance the guest's own script closed can land on a reopened same-key instance within the TTL. B's 'credits' were deliberately deferred; the scene-nonce purge and the TTL bound it.
- C2 alone runs on the at-most-once FIFO (WIRE-1): a frame dropped on a bridge redial strands that line until the orphan rule, which may pick Cancel instead of the host's choice. C2 also leaves polled windows guest-driven. Both are fixed in C3.
- A UI dialog (Id 9; for example FieldHUD's 'Skip movie?', tutorials) that is open at the same time as a locked ETb line cannot be answered by the guest, because the guard swallows all dialog keys while any locked line is open. This is rare.
- Threading: VA taps run off the main thread (VoicePlayer.cs:84-108, :234, :273). Ring appends must stay under _ringLock, BuildStateFrame must only run on the main thread via the dirty flag, and IsGuestLockedDialog must read only volatile fields plus a copy-on-write Local array.
- Hot-path edits: the EBin B_KEYON/B_KEY hoist must keep the left-first evaluation and the exact Int32 & UInt32 -> Mathf.Abs type chain, and EventEngine.cs:119 gains an inert KeyTick++. Both need a vanilla-parity bench and stack-replay capture; EventEngine.cs, EBin.cs, DialogManager.cs and VoicePlayer.cs gain new hunks.
- DIO-1/DIO-2 are not fixed: after every host battle the guest's field cold-starts through Main_Init and relocates the guest. The owner may perceive this as the same 'warp'.
- Mixed versions: C1 and C2 are wire-compatible, so a half-updated pair half-works silently; a C3 v14/v13 mismatch is refused silently on the relay (WIRE-5). Both machines must update every stage.
- Bandwidth: about +0.4 KB per state frame (+12 KB/s at the 30 Hz re-send) plus out-of-band pushes per line or cursor move, on top of the existing ~90 KB/s (WIRE-7).
- Quad deferral: a quad handler that moves the player BEFORE opening its window (a 'Climb?' prompt) still moves the guest by script once it is relayed.
- Quad promotion is not tied to the quad's own handler (a window carries no reliable owner: in a one-level census of the HW exports' Region*_SpeakBTN handlers, 13 of ~313 that open a window do it through another actor, so a speaker filter would cost those, e.g. Daguerreo's weaponsmith counter (test2_562 Region7), and 34 open it asynchronously, so a "handler still running" test would cost those). C1 drops a quad whose handler moves the player more than 100 units with control off before any window, which covers an ambient line mid-climb and the scene a climb leads into. Residual: an unrelated line rising in the beat before the handler's first move (a turn, a jump wind-up) still promotes the ladder. A handler that moves the player without taking control is also not seen.
- C1 talk relay without catch-up: a deferred start is retired once the host's scene for it has risen and fallen (the C1 flag also falls in a window gap, so a long scene can retire it at its first gap). A start first seen only after its scene ended (a late arrival, TALK-7) still opens late and un-driven until C2/C3.
- C1 auto-teleport: the per-window C1 flag is held 5 s past its last high read, so with the 4.5 s dwell an opt-in auto-teleport can still fire in a host windowless beat longer than about 9.5 s. C2's sticky scene flag closes this.
- EventCollision.sSysAngle (set at :106 before the spectator gate) is not carried, so the few handlers that read the talk angle see the guest's stale value. This is cosmetic.
- Harness calibration: coop_dialogue_lockstep.py (B5 'local advance restored' and the L1 pin checks) and coop_talk_relay.py encode the old contract. They must be rewritten, and every new check proven to FAIL on the pre-change DLL first (memory: a check that cannot fail).
- The engine build auto-deploys over the live install: use py tools/build_memoria.py (backup plus sha verify), capture each stage as its own sNN after s94 (README is authoritative; note the two distinct s48 patches), and gate with tools/memoria_stack_replay.py.
