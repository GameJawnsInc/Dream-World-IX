# External Research: How Powerful Creative/Dev Tools Stay Approachable — Patterns for the FF9 Workspace

Research pass for the Workspace GUI makeover. The mandate — "great for experts AND accessible to less-technical users, simultaneously" — is the exact problem every mature creative/dev IDE has had to solve. The good news: the field has converged on a small, repeatable set of moves. The bad news for this app: its current shape (10 flat peer tabs, always-on inspector density, jargon on the surface) is closer to the *before* state of these tools than the *after*. Below is a cited pattern library, case studies, and an opinionated top-5, each mapped concretely onto this app's real structure (`workspace/shell.py` QMainWindow, the 10-tab `QTabWidget`, the Ctrl-K pill, the left journey▸campaign▸field▸object tree, the right inspector, `style.py`/`editor/theme.py`).

The single most important finding, stated up front: **in every one of these tools, the power-user escape hatch (command palette / keyboard) is what *permits* the visible surface to be simplified.** You do not choose between dense-for-experts and simple-for-newcomers. You build a fast hidden lane for experts, and *that* frees you to make the visible lane calm. This app already has the hatch (Ctrl-K) — it just hasn't yet spent the simplification budget that the hatch buys.

## Part 1 — PATTERN LIBRARY

Each pattern: what it is · exemplar · how it maps onto this app · effort/impact.

### P1 — Task-based Workspaces (regroup flat tabs into intent-scoped modes)
**What:** Replace a flat wall of always-visible panels with a small set of named *workspaces*, each pre-arranged for one task, switchable from a top tab strip. The user picks *what they're trying to do*, not *which panel*. Blender 2.8 turned its old "Screen Layouts" menu into visible **Workspaces** tabs (Layout, Sculpting, Texture Paint, Motion Tracking…), each a preset arrangement, "quicker and easier to switch, rename, delete and add through available presets" ([Blender 2.80 release](https://www.blender.org/download/releases/2-80/); [Blender Studio: Workspaces](https://studio.blender.org/training/blender-2-8-fundamentals/workspaces/)). DaVinci Resolve does the same with its 7 **Pages** (Media, Cut, Edit, Fusion, Color, Fairlight, Deliver) — "dedicated workspaces designed for each stage of post-production" ([2-Pop: Resolve interface & pages](https://2pop.calarts.edu/technicalsupport/davinci-resolve-interface/)).

**Maps onto:** The 10 tabs (Home, Editor, Map, Story State, Item & Equip, Battle, Models, Build & Deploy, Import, Co-op) in `shell.py` are today *peers with no cohesion* — exactly the "unclear cohesion" the brief names. They cluster naturally into ~4–5 *workspaces*: **Build a Room** (Editor+Map+Story State), **Tell a Story** (Import+Story State+campaign graph), **Fight** (Battle+Models), **World** (overworld), **Ship It** (Build & Deploy+Co-op). A newcomer sees "what do you want to make?" not "here are 10 things you don't understand." The `QTabWidget` stays as the implementation; you add a top-level workspace switch above it (or collapse tabs per workspace).
**Effort:** Med (reparent existing docs, no new backends). **Impact:** High — this is the single biggest cohesion win.

### P2 — Command palette as the power-user escape hatch (and the simplification enabler)
**What:** A keyboard-summoned "run anything by name" surface. VS Code's Command Palette is "the central hub for command discoverability, enabling both casual and power users to locate functionality without memorizing menu structures" — with **category prefixes** for scannability, **plain verb-first names**, and inline **keybinding hints** ([VS Code Command Palette guidelines](https://code.visualstudio.com/api/ux-guidelines/command-palette)). It is the reason VS Code can keep its chrome minimal: anything not on screen is one `Ctrl-Shift-P` away.
**Maps onto:** The app *already ships* a Ctrl-K search pill (`shell.py`). Upgrade it from "search" into a true command palette: (a) verb-first entries ("Deploy field to test slot", "Fork a real field…", "Open Info Hub → Models"), (b) **category prefixes** ("Build:", "Story:", "World:", "Learn:") so results are scannable, (c) show the **keybinding** beside each (F9 Deploy, F6 in-game), (d) include *navigation* (jump to any tab/field/object) *and* *actions* *and* *docs* in one list. Once this exists, you can safely hide rarely-used toolbar buttons — experts type them.
**Effort:** Low-Med (the pill exists; enrich its index + rendering). **Impact:** High — it's the lever that makes P4/P5 (surface simplification) safe.

### P3 — Progressive disclosure: Beginner ⇄ Advanced (global mode + per-form "Advanced" sections)
**What:** Show frequent/essential controls first; defer rarely-used/expert controls to a secondary tier reached on request. NN/g's authoritative framing: a **two-tier split**, primary = "features users access frequently / novice users need immediately," secondary = "rarely-used specialized settings, advanced configurations"; it improves **learnability, efficiency, and error rate** simultaneously; keep to **two levels max** and make the "way in" obvious with strong labels ([NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)). Measured effect: "cuts time to first action 30–50% while keeping 70–90% feature discovery" ([UXPin](https://www.uxpin.com/studio/blog/what-is-progressive-disclosure/)). Real exemplars: macOS Settings ("Advanced…" secondary window), Google Search vs Advanced Search, ChatGPT's single box with "massive capability lurking beneath" ([same UXPin/ixdf sources](https://ixdf.org/literature/topics/progressive-disclosure)).
**Maps onto:** Two moves. (1) A **global Beginner/Advanced toggle** (gear menu / status bar) that hides the jargon-dense fields — `mesID`, `gEventGlobal` band, `scenario`, raw id bands — until Advanced is on. (2) Per-form **collapsible "Advanced" accordions** in the Qt forms (`editor/forms.py` → `forms_qt.build_form`): a field's Beginner form is name + art + exits; everything else folds away. This is the direct antidote to "smushed text, dense regions." The forms are generated centrally, so one disclosure mechanism covers every pillar.
**Effort:** Med (one flag threaded through the form builder). **Impact:** High — hits the brief's exact complaint.

### P4 — Welcome / Walkthrough onboarding (a Home that teaches by doing)
**What:** A first-run surface that is a **multi-step checklist with rich media and one action per step**, tracking progress. VS Code's Walkthroughs guidelines: "a consistent experience for onboarding users via a multi-step checklist featuring rich content"; **rules**: every step has an **actionable, verb-first item** ("View all Commands"), images that **clarify not decorate**, theme-aware assets, and **don't make walkthroughs too long** ([VS Code Walkthroughs](https://code.visualstudio.com/api/ux-guidelines/walkthroughs)).
**Maps onto:** The app already has a **Home tab** — today likely a static landing. Turn it into a tracked walkthrough: "**Deploy your first room in 5 steps**" (New from sample → Open Editor → change the name → F9 Deploy → F6 in game), each step a verb button that *navigates the app and highlights the control*. Progress persists (`prefs`). A second walkthrough: "Fork a real FF9 field." This teaches the workflow *and* the vocabulary in the order the user needs it, instead of dumping 15 unknown nouns at once.
**Effort:** Med. **Impact:** High for newcomers, zero cost to experts (they skip it).

### P5 — Templates & sample gallery ("don't start from blank")
**What:** New users start from a working example, not an empty form. Blender ships **application templates** and workspace presets so you "quickly get started with tasks" ([Blender 2.80](https://www.blender.org/download/releases/2-80/)). RPG Maker ships sample projects; the *absence* of this is a top Obsidian complaint — "a fresh vault is completely empty… no templates, no suggested workflows, no guided onboarding" ([Obsidian onboarding critique](https://digitalbiztalk.com/article/why-obsidian-gets-better-the-longer-you-use-it-2026-guide)).
**Maps onto:** The repo is *full* of proven, shippable examples — the Stolen Ember campaign, the twin-altar co-op showcase, vivi-hut, continent-v1. Surface a **"New from sample" gallery** (thumbnails via the existing `thumbs.py` service) on Home / in the New menu: "A simple room," "A room with an NPC and dialogue," "A two-field story," "A co-op door." The newcomer gets something that *runs in-game today*, then edits it — the safest possible on-ramp, and it doubles as living documentation.
**Effort:** Low-Med (examples exist; wrap them in a picker). **Impact:** High.

### P6 — Contextual, selection-scoped panels (the inspector shows only what's relevant)
**What:** Side panels re-render to match the current selection, so density is *task-local* rather than *always-on*. Figma's right panel is the canonical case — properties change entirely based on what's selected — an application of contextual progressive disclosure ("offering additional information based on the user's current actions," [Figma/UXPin progressive disclosure](https://www.figma.com/resource-library/ui-design-principles/)). Godot's Inspector behaves identically against the scene tree.
**Maps onto:** The right **inspector** in `shell.py` should be strictly selection-driven: pick a *gateway* in the tree → inspector shows only gateway fields + a one-line "what a gateway is"; pick a *field* → field props. Avoid showing all object types' controls at once. Pair with P3 so even the contextual panel opens Beginner-first.
**Effort:** Med. **Impact:** Med-High (directly reduces on-screen density).

### P7 — Teach domain vocabulary in-context (hover glossary + info scent)
**What:** Define jargon *where it appears*, not in a manual the user won't open. Blender's tooltips embed the Python op name and link to the manual; good IDEs give every unfamiliar term a hover card. The brief's vocabulary list (journey, campaign, field, fork/verbatim/native, walkmesh, gEventGlobal, gateway, mesID, scenario) is explicitly called "a core learnability problem."
**Maps onto:** A tiny **glossary service**: any label/term rendered with a dotted underline shows a 1–2 sentence definition + a "Learn more" link on hover (`QToolTip` / a custom hover card). Seed it from the CLAUDE.md glossary you already maintain. Add a **"Concepts" entry** in the Info Hub. Critically: label with **plain language on the surface, jargon in the tooltip** — "Story flag (gEventGlobal)" not "gEventGlobal 8512". VS Code's rule applies: "avoid jargon; clarity trumps brevity" ([palette guidelines](https://code.visualstudio.com/api/ux-guidelines/command-palette)).
**Effort:** Low (data-driven, reuses tooltips). **Impact:** High per-dollar — cheapest direct hit on the newcomer problem.

### P8 — Minimize first-run friction (defaults over decisions)
**What:** Every up-front choice is a chance to lose a newcomer. Godot's celebrated on-ramp: "no install wizard, no version manager, no licence to scroll — you unzip, double-click, and you're in," explicitly contrasted with **Unity Hub's "higher first-week friction: version selection, project templates, render pipeline choice — all decisions before you've written any code"** ([OceanView: Unity vs Godot vs Unreal 2026](https://dev.to/oceanviewgames/unity-vs-godot-vs-unreal-for-beginners-2026-which-engine-should-you-start-with-575l); [Meshy: Godot vs Unity](https://www.meshy.ai/blog/godot-vs-unity)).
**Maps onto:** The `setupdialog.py` / `provision` flow should have a **"Just get me started" default path** that picks sensible defaults (test slot 4003, the master mod folder from `.ff9deploy.toml`) and defers every optional choice to later. Don't ask a newcomer to understand id-bands or mod-folder stacking before they see a room.
**Effort:** Low-Med. **Impact:** Med-High (retention at the riskiest moment).

### P9 — The tree as the mental model, made visible (scene-tree pattern)
**What:** A single, consistent hierarchical model the user learns *once* and applies everywhere. Godot's whole approachability thesis is one idea — "everything is a scene; scenes contain nodes" — "more intuitive than Unity's component system" ([Meshy](https://www.meshy.ai/blog/godot-vs-unity)). The tree teaches the domain's structure by being the primary navigation.
**Maps onto:** The left **journey▸campaign▸field▸object tree** *is* this app's scene tree — lean into it hard as the teaching spine. Make it the canonical "where am I" model, keep the breadcrumb in sync, and (with the existing `mapview.CampaignMap` graph) offer a visual "map of my project." One learnable hierarchy > 10 disconnected tabs.
**Effort:** Low (exists; elevate it). **Impact:** Med-High.

### P10 — Persistent next-action hints + non-modal feedback (status line)
**What:** A quiet always-present line telling the user *what they can do next / what state they're in*. Blender's 2.8 redesign added status-bar hints and keymap hints so the user is never guessing the next input.
**Maps onto:** The bottom **Problems·Output dock** in `shell.py` can carry a persistent hint strip: "Room built ✓ — press **F9** to deploy, then **F6** in-game." Turn `editor/feedback.py` Verdict/Problem output into *actionable* rows (click a problem → jump to the offending field). Guides without modal interruption.
**Effort:** Low. **Impact:** Med.

### P11 — Low-stakes sandbox entry point (play before you commit)
**What:** Give beginners a consequence-free place to experiment before the "real," committing workflow. Ableton's **Session View** is the exemplar: "a non-linear workflow that allows music makers to explore ideas without a defined start or end point… experiment without committing to a structure" — you can "have a 16-bar loop sounding good within 30 minutes" ([Ableton: Session View](https://www.ableton.com/en/classroom/support/first-steps-ableton-live/lesson-session-view/); [Sweetwater](https://www.sweetwater.com/insync/5-tips-getting-started-ableton-live/)).
**Maps onto:** The dev **test slot (4003)** + F6 hot-reload loop is already this app's Session View — a fast, reversible sandbox. Surface it as such: a "**Try it now**" affordance that deploys the current thing to the scratch slot with one click, framed as safe/reversible ("this won't touch your real project"). Make the fast loop *the beginner's first experience*, not an expert secret.
**Effort:** Low (loop exists; reframe + one button). **Impact:** Med-High.

## Part 2 — CASE STUDIES (tool → the ONE move → our analog)

**1. Blender 2.8 — the "Blender is hard" reckoning → the ONE move: task Workspaces + familiar defaults.** Pre-2.8, Blender demanded hotkey fluency and used right-click-to-select, "confusing for beginners"; 2.8 switched to left-click-select and, decisively, converted screen layouts into visible **Workspaces tabs** with presets ([Blender 2.80](https://www.blender.org/download/releases/2-80/); [Steam guide](https://steamcommunity.com/sharedfiles/filedetails/?id=1656371184)). **Our analog:** collapse the 10 flat tabs into ~5 intent workspaces (P1); adopt the "familiar default" spirit — plain-language labels on the surface, engine jargon in tooltips (P7).

**2. VS Code — deep tool, calm surface → the ONE move: the Command Palette.** Everything is reachable by name from `Ctrl-Shift-P`, so the chrome can stay sparse; walkthroughs onboard the rest ([palette](https://code.visualstudio.com/api/ux-guidelines/command-palette); [walkthroughs](https://code.visualstudio.com/api/ux-guidelines/walkthroughs)). **Our analog:** promote the existing **Ctrl-K pill** to a categorized, verb-first, keybinding-annotated command palette (P2) — the escape hatch that lets you simplify everything else.

**3. Godot — beginners actually ship → the ONE move: zero-friction entry + one mental model.** "Unzip, double-click, you're in," and *everything is a node/scene* ([OceanView 2026](https://dev.to/oceanviewgames/unity-vs-godot-vs-unreal-for-beginners-2026-which-engine-should-you-start-with-575l)). **Our analog:** a "just get me started" default setup path (P8) + treat the **journey▸campaign▸field▸object tree** as the one hierarchy the user learns once (P9).

**4. DaVinci Resolve — 7 stages, still teachable → the ONE move: Pages that mirror the mental model.** Each Page is a workspace tuned to one post-production stage, and beginners are told to start on the friendly ones; "features designed to make it easier for new users to get great results while they continue to learn the advanced tools" ([Blackmagic](https://www.blackmagicdesign.com/products/davinciresolve); [2-Pop](https://2pop.calarts.edu/technicalsupport/davinci-resolve-interface/)). **Our analog:** name workspaces after the *goal* ("Build a Room," "Tell a Story," "Ship It"), not the artifact, so the switcher itself teaches the workflow (P1).

**5. Bethesda Creation Kit — the anti-pattern → the lesson: don't ship the raw engine's mental model.** Modders call it "the least intuitive mod-maker I've ever seen… its own moon logic," "slow, prone to crashes, unintuitive, undocumented" — so bad the community built a replacement IDE, Creation-Companion ([Modding.wiki: Creation Kit](https://modding.wiki/en/skyrim/developers/creation-kit); [Creation-Companion](https://github.com/Elscrux/Creation-Editor)). **Our analog:** this app's danger is identical — it's a wrapper over a hardcore engine (Memoria, `.eb` bytecode, gEventGlobal). The Creation Kit failed by exposing engine internals raw. This makeover must **wrap** them: plain labels + progressive disclosure (P3) + in-context vocabulary (P7), never the raw ids on the front surface.

**6. Ableton Session View — play before commit → the ONE move: a non-linear sandbox as the first experience.** Beginners make music in 30 minutes because Session View removes the commitment of the timeline ([Ableton](https://www.ableton.com/en/classroom/support/first-steps-ableton-live/lesson-session-view/)). **Our analog:** frame the **4003 test-slot + F6 hot-reload** loop as a safe "Try it now" sandbox and make it the beginner's *first* click (P11).

**7. Obsidian — power via opt-in complexity → the ONE move (and its trap).** "Simple by default… no onboarding wizard trying to guess your use case," complexity discovered "as you need it" via community plugins ([Obsidian philosophy](https://digitalbiztalk.com/article/why-obsidian-gets-better-the-longer-you-use-it-2026-guide)). But the *trap*: the empty vault has "no templates, no suggested workflows, no guided onboarding," and reviewers say productivity "requires understanding Markdown, YAML front matter, folder structures, and a handful of plugins." **Our analog:** keep opt-in complexity (P3), but *don't* replicate Obsidian's blank-canvas mistake — pair minimalism with **templates + walkthroughs** (P4, P5) so "simple by default" doesn't become "abandoned at the blank form."

## Part 3 — TOP 5 PATTERNS TO ADOPT (opinionated)

Ranked by fit to *this* app's specific gap — cohesion, density, and teaching an intimidating vocabulary — and by leverage per unit of effort.

**1. Regroup the 10 flat tabs into ~5 task-based Workspaces (P1).** *Why first:* the brief names "unclear cohesion" and "smushed, dense regions"; ten peer tabs with no grouping *is* the incoherence. This is the highest-impact structural move and reuses every existing doc/backend — you're reparenting, not rebuilding. It also gives newcomers a "what do you want to do?" entry that the current tab wall actively denies them. Blender and DaVinci both prove it scales to expert workflows. (Med effort, High impact.)

**2. Ship a global Beginner/Advanced toggle + per-form "Advanced" accordions (P3).** *Why:* this is the literal, measurable fix for "smushed text, dense regions" and for the jargon problem — hide `mesID`/`gEventGlobal`/`scenario` until asked. NN/g documents it improving learnability, efficiency, *and* error rate at once, with a 30–50% faster time-to-first-action ([NN/g](https://www.nngroup.com/articles/progressive-disclosure/); [UXPin](https://www.uxpin.com/studio/blog/what-is-progressive-disclosure/)). Because the Qt forms are generated centrally (`forms_qt.build_form`), one disclosure mechanism covers all ~36 pillars. Experts flip Advanced on once and lose nothing. (Med effort, High impact.)

**3. Promote Ctrl-K into a real command palette (P2).** *Why:* it's the enabler for 1 and 2 — you can only calm the visible surface if power users have a fast lane to everything. The pill already exists; enriching it with verb-first names, category prefixes, keybinding hints, and unified nav+action+docs search is low-effort, high-leverage, and directly follows VS Code's proven guidelines ([palette](https://code.visualstudio.com/api/ux-guidelines/command-palette)). Adopt this *alongside* #1/#2, not after — it's what makes them safe. (Low-Med effort, High impact.)

**4. Turn Home into a tracked Walkthrough + a "New from sample" gallery (P4+P5).** *Why:* the vocabulary problem is fundamentally a *sequencing* problem — teach the nouns in the order the task needs them, not all at once. A 5-step "Deploy your first room" walkthrough (verb-first steps that drive and highlight the UI) plus a gallery of the repo's already-proven examples (Stolen Ember, twin-altar, vivi-hut) gives newcomers a running artifact in minutes and avoids Obsidian's blank-canvas trap. Both pieces reuse assets you already have. (Med effort, High impact for the target audience.)

**5. In-context vocabulary teaching: hover glossary + plain-label/jargon-in-tooltip (P7).** *Why:* it's the cheapest direct hit on the explicitly-flagged "core learnability problem," and it compounds with everything above (walkthrough steps, inspector fields, palette entries all get the same hover cards). Seed it from the glossary you already maintain in CLAUDE.md. Rule to enforce everywhere: **plain language on the surface, engine term in the tooltip** — "Story flag" on the label, "gEventGlobal, save-persistent" on hover. This is what separates a wrapped tool from a Creation-Kit-style raw-engine exposure. (Low effort, High impact-per-dollar.)

**The through-line:** #3 (hatch) makes #1 and #2 (simplify the surface) safe; #4 and #5 (teach) make the simplified surface *learnable* rather than merely emptier. Adopt them as one coherent move — a hidden fast lane for experts, a calm taught lane for newcomers, sharing one project tree (P9) and one sandbox loop (P11) — not five isolated features.
