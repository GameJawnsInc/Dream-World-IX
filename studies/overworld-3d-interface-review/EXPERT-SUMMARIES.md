# Expert panel executive summaries (pre-verification)

## geometry-pipeline

The geometry core here is stronger than its size suggests, and I want to say so before the findings. I read the 1,246 `.ff9mesh` files currently deployed to the live install and re-derived their structural properties independently of the toolkit: **zero** unindexed-contract violations, **zero** malformed headers, **zero** trailing-byte corruption, and — after calibrating against all 260 real disc-1 blocks — an engine-rejected-triangle rate on custom Terrain (502/45,127 = 1.1%) that is *below* stock's own (3,439/83,939 = 4.1%). The worst-looking custom blocks turned out to be byte-faithful carries of stock blocks (0,0) and (17,2). The sea-normal law is honoured in practice: 254,915 of 255,385 deployed Sea4 vertices carry the measured byte constant (-0.1211, 0.9785, 0.1665) and **none** carry the naive (0,1,0). That is a genuinely clean pipeline, and the reason is architectural, not lucky: every builder funnels through one write seam (`mesh.write_ff9mesh`) and every transform rebuilds a fresh triangle soup rather than mutating an indexed mesh, which makes `vcount == icount` true by construction. `meshedit.py` is best-practice work — each law enforced at the call site, each with the falsification that motivated it recorded inline, each covered by a test that fails when the law is removed. The generators fail closed (`island.landmass` refuses to deploy on `not report["clean"]`; `interior` raises on 30+ distinct geometry conditions). Where the practice is weak is not the mesh math — it is the **boundary layer**: the deployed artifact carries no identity, the primary automatic walkability gate is measurably blind to small holes (I broke it: a single deleted triangle on a real 647-tri block leaves the census green 3 times in 12), the engine's part-registration order — the single most consequential ordering fact in the whole simulator — is hardcoded four times in three mutually inconsistent orders, and the one authoring path that puts a human's hands on the geometry (the Blender OBJ round-trip) is also the one with essentially no validation and a documented, unguarded data-loss mode. Fix the boundary and this pipeline is professional-grade.

## tools-ux

This is an unusually strong offline geometry pipeline hobbled by a single missing organ: it cannot show you anything. Take the praise seriously first, because it is load-bearing for the recommendations. The data model is disciplined — one canonical `BlockMesh` (`extract.py:182-219`) that every one of the 29 modules speaks, with the raw Unity buffers retained for lossless re-encode. The two checks that guard the actual byte-write boundary are enforced where they belong and cannot be skipped by a new caller: the unindexed-contract assert (`mesh.py:71-74`) and the off-grid refusal (`mesh.py:43-57`, called from both deploy paths), with the module docstring explicitly explaining that low-layer placement is deliberate. `placement.py` is a byte-exact reproduction of the engine ground query and — contrary to the usual pattern in this codebase — its MISS gate is genuinely wired to raise at the call sites (`island.py:1000`, `interior.py:2459`), not merely documented. `--dry-run` reaches 21 of 32 verbs. Best of all, `transplant.py:2937-2970` gets the hardest thing right: it judges misses DIFFERENTIALLY, admitting the ones the donor itself inherits and rejecting only introduced ones — the "compare against the neighbour, not the marginal" principle that the project paid thirteen playtests to learn, already encoded in production code. And the Workspace World tab (`workspace/worlddoc.py`) is a well-built, correctly-scoped read-only atlas with a disciplined no-I/O-uninvited construction law. This team knows how to build instruments. That is precisely why the central finding stings: the toolkit authors a textured 3D world and ships zero ability to render a triangle. The only engine-faithful rasterizer — 489 lines, UNLIT because the engine binds no normal, with a per-pixel triangle-owner buffer for seam forensics — lives in `studies/path-d-new-world/render_gate.py` hardcoded to one disc, one mod folder, six bench cells and six literal camera positions from the V-shore corner. The cost is measured, not hypothetical: eight rounds chasing a ground-junction defect with zero images taken, and three defect classes closing in a single day once stills finally appeared. The human is not merely the playtest oracle here — a defensible constraint — the human is the *renderer*, which is not. Around that hole cluster the other structural gaps: the crack detector the kit wrote, documented and unit-tested (`test_find_tjunctions_sees_what_a_weld_audit_cannot`) has zero production call sites, and the weld audit runs in one builder out of nine, leaving every mint-heavy verb ungated for exactly the defect class the arc named as the seam carrier; the one bridge to a 3D DCC (`world-mesh-export`) reads pristine stock bundles only and has no `--mod-folder`, so an author cannot open their own deployed island in Blender, covers 2 of 8 mesh parts, and emits no material; the movement simulator that `coast_lint.py` calls "the oracle" is a study script while the 99-line static point probe is what ships; and 351 study scripts including 14 separate renderers sit with no promotion path, so each new defect class costs a new bespoke instrument. The through-line is that this project builds excellent instruments and then leaves them where they were born. My recommendations are therefore almost entirely promotion and wiring, not invention — every capability I am asking for already exists somewhere in this repository, tested, in a file that only one site can use. Sequence them: render first (it is the axis with a 0-of-13 predictive record and the only one where a picture substitutes for a relaunch), then wire the existing crack gates at the write seam (a small change closing a named repeat failure), then the deployed-bytes glTF inspection path, then the walk oracle. None of these author geometry, so none of them touch RESHAPE-not-OVERLAY or re-open any falsified synthesis lane; they change only what the toolkit can *see*, which by this project's own retrospective is where its rounds are being spent.

## procedural-content

The carry-vs-mint doctrine is architecturally sound and, at its core, genuinely composable — this is not an accretion of per-case verbs. `transplant.py` is a single coherent carry engine (one gather → rotate → shift → clip → gate → deploy pipeline, transplant.py:2715-2997) parameterized by a small mutation IR, and the 6,880 lines of `coastmorph.py` compile every cliff/beach/sand/cap verb down to just four of that IR's primitives (DropTris, EmitTris, VertexDisplace, SeaBump). `fuse.py` is a model of the doctrine done right: 223 lines that state the law (land cannot be knitted, water can), certify it row-by-row, and refuse. `coastscan.py`'s "the builders are the oracle — the scanner re-implements none of it" is exactly the discipline that prevents catalog drift, and `meshedit.py`'s construction-time refusals (walk-visibility, texel density, weld-exactness, winding) show the team knows how to encode a law at a call site rather than in a docstring. The `--in-place`/frame-safety and read/write disc-split reasoning is unusually careful for a solo-maintained codebase. The failures are not in the carry engine; they are in the three layers above and around it. First, composition itself is imperative and undurable: only `world-fuse` consumes a spec, 28 of 32 world verbs are flags-only, `island.landmass` overwrites deployed blocks with no guard while the interior verbs read those same bytes as input — and the project has already paid for this, losing Grimhorn's falls to a later island run with "no runnable script" for reconstruction, the same class of failure that cost twelve playtests on the Path D bench. Second, the knowledge that would make the next composition job cheap is stranded in markdown: three completed grammar studies (48 blocks, 62 components, ~10k instance pairs) produced fully encodable numeric envelopes — crest displacement ≤2.4u, segments never under 4.00u, turns 82% under 30°, fv=0 pinned at the crest, row-10 at 53% share and +0.12 v-phase — and not one of them appears anywhere in `world/*.py`. Third, the boundary the project paid ~13 playtests to learn is invisible to the code that enforces it: `world-island --beach` is falsified in CLAUDE.md §8 yet ships as an uncaveated, untested, confidently-documented CLI flag, while the one function that got the treatment right (`deepen_shallow_plan`: "DEAD END, SUPERSEDED — kept for the measurement, NOT exposed on the CLI") proves the convention costs three lines. Compounding all three, the gate battery is hand-assembled per builder — `weld_audit` runs on 2 of ~8 write paths, `find_tjunctions` on none outside its own tests, and `morph_in_place`, the riskiest write in the toolkit, runs neither. The through-line is a single organizational gap, not a technical one: this project reliably promotes a *builder* from study to kit (meshedit, interior, texgates all say so in their docstrings), and reliably fails to promote a *composition* or a *judgment*. The highest-value work here is small and mostly plumbing — a grammar constants table, a shared gate battery, a `spec()` method on eleven tweak classes, a `donors.toml` mirroring the field pillar's `region_catalog.toml`, and a site-parameterized renderer — none of which requires new geometry code, and all of which convert institutional memory that currently must be read into machinery that runs.

## spatial-math

The spatial-math foundations of this toolkit are stronger than its size and history would predict, and the strong parts should be protected rather than refactored. Three things are genuinely best-practice for a pipeline of this kind. First, the cell-tag family in `world/entrance.py:47-79` is a model of how to own a coordinate convention: bidirectional `pack_cell_tag`/`unpack_cell_tag`, range validation stated against the ENGINE'S bit width with the reason in the docstring, one `CELL_SIZE` literal, and a real round-trip property test plus engine-verified fixtures at `tests/test_world.py:520-545` — a prior 7-bit-vs-6-bit mask defect was found and is now pinned. Second, the 24x20 block grid is single-sourced at `mesh.py:32-34`, enforced at the lowest write layer (`require_block_in_grid`, called from `deploy_override:193` and `deploy_donor_sidecar:169` rather than per-call-site), and covered by a dedicated `test_world_grid_bounds.py` that includes an explicit "all modules re-export the ONE literal" test. Third, `transplant.py`'s z-adapter (`_ZC = 2048.0`, `_z_in_poly`/`_z_out_poly` at transplant.py:2042-2059) is the correct way to reuse an axis-specific algorithm: an exact swap-plus-sign-flip-plus-power-of-two-shift, documented as bit-exact in float64 so weld-by-identity survives the round trip, with the inverse written next to it. That is careful engineering, and the fork of the field lane's import-frame heuristic disease has not happened here.

The defects are all of one shape: the disciplines above were applied to the conventions someone got burned by, and nowhere else. There is exactly one named frame transform in the whole package (`extract.block_world_origin`) and NO inverse — `world→block` is re-derived inline at eight-plus sites and `64.0` appears as a bare literal 83 times in `transplant.py` alone; `BLOCK=64` is an independent declaration in six modules; and the 4u lattice index exists in two mutually incompatible Z-sign conventions (raw-Z in coastmorph/interior/island/islandbeach/texgates, negated-Z in rimretile/water) with the same generic name and no way to tell them apart from a call site. The engine's world is toroidal on both axes (WMWorld.cs:1344/1452), which exactly two modules know — each with its own extent constant, one of them wrapping only X — while `terrain.reshape` silently drops the wrapped half of a seam-crossing edit and `extract.blocks_touched` advertises a "crack-free" guarantee that is false there. Most consequential, the validation layer has drifted from the geometry it validates: `interior.census_gate` (the gate for `world-forest`/`world-hill`/`world-mountain`) censuses against an UNCUT full-cell Sea4 plane while the island lane deploys a CUT one, which makes its `MISS == 0` predicate unreachable for the terrain-hole class it exists to catch; and the calibrated 2026-08 walk-query implementation lives in `studies/path-d-new-world/walk_sim.py`, re-forked rather than imported, gating no build, while the superseded model in `world/placement.py` — which has no dedicated test file and no representation of the 0x31EE veto, the cache ring, or the two registration-order exceptions — gates every generator. Given this project's own measured record that gates were 0-for-13 predictive on the Path-D arc, the highest-leverage work here is not new capability: it is making the gates score the bytes that actually ship, and giving the coordinate conversions one home with round-trip tests, so the next sign error is a red test instead of a playtest verdict.

## validation-qa

This project's *research-side* verification practice is, honestly, better than most AAA teams I audit: predictions registered before the instrument is built (`RENDER-GATE.md:42-59`), calibration-before-judging enforced as a rule and shown with numbers (`texgates.py:37-57` refuses to judge blind rather than ship a gate that would reject a verbatim carry), standing blind-spot ledgers (`RENDER-GATE.md:61-69`), adversarial skeptics who refuted 5 of 6 of their own study's laws, and a reproduce-from-anchor pipeline that killed a silent-revert class (`bench_pipeline.py`). The kit's write boundary also carries two genuinely load-bearing, unconditional guards (`mesh.py:71-74` unindexed contract, `mesh.py:43-57` off-grid refusal), and `transplant.py:2935-2972` contains the single best gate in the codebase — a *differential* census that permits only misses the donor itself has. That is the right pattern and it should be the template for everything else.

The failure is not rigor; it is **transfer**. Every instrument that demonstrably predicted a defect lives in `studies/` as a bench-hardcoded script, and none of it is reachable from the 31 shipped `world-*` verbs. The renderer that reproduced three consecutive playtest failures offline is 489 lines pinned to disc 9 and six cell coordinates. GATE T and the walkability pass — the only gate in the arc red on a build the owner faulted and green on ones he did not, and the only check covering the one defect class that can strand a save — are 133 lines hardcoded to the same six cells. Meanwhile `world-terrain`/`world-reclaim`/`world-coast` deform stock verts and write `.ff9mesh` bytes with **zero** geometry, walkability, texture or tessellation checking of any kind, and `world-transplant` prints `gates CLEAN` while a dirty texture gate is warning three lines above it. So the 0/13 record is not evidence that gates cannot work here — it is evidence that the gates *with* discriminating power were never wired into the path that mints the geometry. The cheapest instrument that would have caught the historical escapes already exists and has already been calibrated; it costs a promotion commit and no new dependency (Pillow is a hard dep, numpy already rides along for the interior verbs). On the test side, the two largest modules (coastmorph 6,880 LOC, transplant 4,169 LOC) are the least covered by anything that runs without the game install, and the nightly gate's collect-floor guard is structurally blind to the module-level `skipif` that silences all 56 coastmorph tests.

## engine-integration

The engine boundary here is, on the whole, unusually well-built for a solo-plus-agents project. The loose `.ff9mesh` override is a genuinely good architectural choice — one write seam (`mesh.deploy_override`), one format, one engine reader, identity-safe when absent — and it buys geometry iteration on Unity 5.2.3 assets that would otherwise require an AssetBundle repack. Three pieces are best-practice by any studio standard: (1) `discmirror.auto_mirror`'s EVIDENCE CONTRACT (`discmirror.py:28-45`, `92-200`) — it derives everything from the actual return values of this call's deploy writes, refuses to guess a game root, and explicitly refuses to mirror a synthetic namespace rather than relying on an accidental exception; (2) the s74 disc-role split (`s74:35-39`, `148-157`), which identified and named a silent-degrade trap (`assetDisc` vs `overrideDisc`) *before* it shipped; (3) `transplant.py:2936-2967`'s differential MISS gate, which maps every introduced miss back through the inverse tweak chain to ask whether the *donor itself* misses there — the "compare against the neighbour, not the marginal" law actually implemented rather than merely written down. The `placement.py` ground-query simulator is a byte-level RE of `w_nwpHit` and is the right idea. My concerns are not about the design; they are about a systematic asymmetry at the boundary itself. **Everything the kit validates, it validates against its own intent. Nothing in this pillar ever reads back what the runtime actually built, what it rejected, or what is currently on disk.** The engine-side ground-truth instrument for exactly this was written, shipped in s22, and has zero consumers anywhere in the repo. The runtime's rejection paths log to a file no tool in this project reads, and on reclaimed sea cells a rejected override does not fall back to ocean — it falls back to a *different real block's walkable geometry*, at the wrong coordinates, unlogged. And the deployed world tree (1246 live files, three disc namespaces) carries none of the build-provenance machinery the field pillar already has and uses. That combination is precisely what produced the two retrospectives this project already wrote about itself — "0 of 13 playtest verdicts predicted by a gate" and "twelve playtests sat on a silent regeneration revert." The fix is not more offline gates scoring intended bytes; it is closing the loop on actual bytes. Four of the seven findings below are small-effort and use facilities that already exist.
