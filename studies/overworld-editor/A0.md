## What was built

- `ff9mapkit/workspace/worldview3d.py`:
  - **pure half:** `clip_matrix` (render.project as a matrix), `pack` (render.load_batches output to unindexed
    float32 per part, batch order kept), `texture_rgba` (alpha-0 to white), `compare` (the defect-class measure),
    `OrbitCamera`;
  - **GL half:** `render_still` (one still in an offscreen context), `WorldView3D` (the QOpenGLWidget: left-drag
    orbit, right/middle-drag pan, wheel zoom, Home re-frames), `WorldView3DPanel` (status / fallback / view).
  - One GLSL 1.20 shader pair; no dependency beyond PySide6 Essentials (`QtOpenGL`, `QtOpenGLWidgets`).
- **The World tab** (`worlddoc.py`): a "3D view" / "Chart view" button in the head row swaps the chart for the 3D
  page over the same census; the details strip serves both; the legend hides in 3D. The GL module is imported, and
  the map read, only on that click.
- **gui_snap:**
  - `world:3d` draws the page from a synthetic scene (pinned, no install);
  - `world:3d-live` reads the real install read-only and is never part of `all`.

## The comparison against `world-render`

**Projection:** `clip_matrix` divided through lands every vertex on `render.project`'s pixel to 1e-13 px (persp and
ortho, odd and even sizes). The software raster samples pixel corners; GL samples pixel centres, so the matrix carries
a half-pixel shift. Without it, 6 tests fail.

**Pixels:** a first per-pixel diff read 0.1-0.9% of pixels "foreign". The diff masks show two precision classes,
neither a defect:
- **1-px lines** on 4u tile edges, where a pixel centre lies exactly on a shared edge. The oracle paints both
  triangles and keeps the first (`b >= -1e-9`, strict depth `<`); GL's fill rule gives the pixel to one of them, so it
  takes the neighbour tile's texel.
- **Isolated dots** on high-frequency rock and grass, where a nearest-texel pick falls on a texel border: float32 on
  the GPU against float64 in the oracle.

A real defect (wrong texture, flipped tile, lost triangle, wrong cull) is an AREA, so `compare` reports `coverage`
(sky in one image only) and `blob` (differing pixels whose whole 3x3 neighbourhood differs):

| scene, camera | differ | coverage | blob | GPU / CPU time |
|---|---|---|---|---|
| V-shore bench (disc 9), the six committed cameras | 0.11-0.51% | 0-2 | **0** | 0.14-0.58 s / 0.4-1.8 s |
| V-shore bench with stock, `island` / `top` | 0.83% / 0.41% | 1 / 0 | **0** | 0.4 s / 2.0 s |
| disc-1 (7,17) coast with stock, `top`, `close`, `graze`, `overview` | 0.23-0.86% | 0-2 | **0** | 0.14-0.42 s / 0.2-1.1 s |
| synthetic (heights, a wall, a down-facing lid, a blank texel corner, an untextured part) | 0.03-0.25% | 0 | **0** | |

**Break-it** (`tests/test_worldview3d.py`, each must give blob > 100):

| mutation | blob | coverage |
|---|---|---|
| texture V not flipped | 61,857 | 0 |
| cull off | 2,080 | 146 |
| a visible batch dropped | 38,509 | 25,753 |
| a culled batch dropped (the first draft of this mutation) | 0 | 0 |

The last row is the lesson: the first draft dropped the down-facing lid, which every camera culls, so the mutation
changed nothing and "passed". The mutation now drops the wall.

## The tests

`tests/test_worldview3d.py`, 15 tests. The pure ones run headless. The two GPU ones run `_worldview3d_native.py` in a
child process on the native platform and skip only when that child reports no GL context. The bench test also skips
without an install. Mutations checked on the code: drop the half-pixel shift (6 red), drop the V flip in the shader
(2 red).

## Not in A0 (named)

- **The x-torus:** the view draws x 0..1536 once, so the map's edge shows sky. The editor will need the wrap before
  relief can be placed across the 23|0 seam (which relief verbs do not support yet either).
- **render.py's blind spots, inherited:** no sea animation, fog, sky or the game's camera path.
- **Load time:** a full rescan in 3D re-reads the whole map (about 5 s). A per-block cache keyed by file identity
  could make a rescan cheap; it is unneeded until the editor redeploys often (C1).
- **Picking** is A1.
