# C1: the forest, end to end

**Status:** built and in-game proven 2026-10-23 (`20261023-125544-c1-lab`, every registered prediction held). Owner
playtest pending. Owner request: "go C1".

## What it does

In the World tab's 3D view, **Add forest** opens a card under the map:

1. **Place.** Click the map where the forest goes. A ghost of the canopy stands there, its rim on the island's own
   ground. Drag the ghost to move it; elsewhere a drag still orbits.
2. **The handles.**
   - *Donor:* the catalogue's five qualified canopies, nothing else.
   - *Angle:* 0-359°, wrapping.
   - *Spread:* ×1.00 to ×`FOREST_SPREAD_MAX`, read from the interior's own constant.
3. **The cheap law, live.** While you move, the footprint law runs as a preview. Off the island or onto rock, stamps
   or the coast, the ghost turns red with marks where it fails ("Not here: the footprint reaches coast rock
   (topograph 58)"), and no job starts.
4. **The check, on release.** When the handles settle, the tool runs `world-forest --dry-run` as a subprocess. Its
   verdict is drawn: green and "Passes every gate…" with the carve's own numbers, or red, the gate named and marks
   at the points it refused.
5. **Accept** runs the same command without `--dry-run`, into a **draft**: the folder's world files copied out of the
   install. The view then draws "With the draft", the draft in place of its folder in the game's FolderNames order.
   **Copy command** copies Accept's command (always aimed at the draft). **Discard draft** asks, then deletes it.

The game never sees a draft. Promoting one into the live folder is C4.

## THE CLI STAYS THE ORACLE

The tool never carves in the Workspace's process. Check and Accept run `world.forestedit.command`'s argv (the one
place the editor spells a command) and read the verdict `world-forest --report-json` writes. So an editor-placed
forest is, by construction, the same call a hand-typed command makes, and the acceptance test checks it rather than
assumes it:
- **hermetic** (`test_worldforest.py::test_the_editor_writes_the_bytes_the_hand_typed_command_writes`): the tool
  accepts into a draft through its own argv, run by `cli.main`; the same forest is typed by hand on a copy of the
  island; every world mesh file is byte-identical, and the source folder is never written;
- **on the real island** (`c1_lab.py build`, I1): the real tool and its real subprocess runner accepted forest-grove
  at (1400, -460) into a draft of FF9CustomMap-world; the hand-typed `world-forest --mod-folder <second draft>
  --center 1400,-460 --donor 13,15` wrote a second; **identical over all 1,531 world files**, two of them edited
  (Block[21][7] and Block[22][7] Terrain).

## The pieces

| piece | where | what |
|---|---|---|
| located refusals (B1, forest gates) | `world/interior.py` `CarveRefused` | a `ValueError` with `gate`, `where` (world points), `detail`; its text is the gate's own, so the CLI prints the same bytes. Footprint, hole, leak, geometry, step law, walk-in, census (MISS, stacked, the probe) |
| the footprint law, lifted | `interior.forest_footprint_lawful` | the carve's placement test as a function; `carve_forest` calls it |
| the verdict as data | `world-forest --report-json PATH` | ok, dry run, centre, the carve's report, blocks, files written, the refusal (gate, message, detail, where) |
| the editor's kit side | `world/forestedit.py` | `canopy_donors`, `outline` (the donor blob as the carve gathers it), `plan_xz` (`_forest_plan`'s map), `placed`, `SoupIndex`, `footprint_preview` (the law vectorised), `command`, `read_verdict` |
| drafts | `world/draft.py` | `ensure_draft` (copy Disc1 + Disc4, no backups, plus the ledger; refuses a root inside the install), `edits`, `stale`, `edited_blocks`, `discard` (only a draft under the drafts root) |
| the tool | `workspace/worldforest.py` `ForestTool` | the card, the ghost, the preview, the jobs (a `QProcess` per job; the runner is a seam), the stale guard (a verdict answers only the handles it was asked about; a moved handle kills the running check) |
| the view | `workspace/worldview3d.py` | `overlays` (translucent, depth-tested ghost; on-top rim ribbon and marks), the draggable ghost (`ghost_moved`/`ghost_dropped`, on the level plane at its rim: `plane_hit`), `ribbon_tris` |
| the tab | `workspace/worlddoc.py` | Add forest on the 3D bar; a pick places the forest while the tool is open; "With the draft" drawing mode while the folder has a draft |
| the snaps | `tools/gui_snap.py world:3d-forest` | passed, refused (marks), preview-refused, from an invented canopy on the synthetic island and a scripted runner |

**The preview is the law.** `footprint_preview` is the carve's footprint loop vectorised, with a bounding-box prefilter
that is exact (a tri whose plan box misses the rim's, grown by the band, cannot be in or near it). It agreed with the
loop on 120 of 120 real placements (51 lawful), and a test holds it to the loop on random centres, turns and spreads
over a patchy field. Dropping its corner test or its coast test turns that test red.

## Timings (measured on the live FF9CustomMap-world)

- A full exact-centre carve with every gate, the walk-in and the census included: **7 s** from a cold CLI; a footprint
  refusal 4-5 s. That answers the plan's open question, and C1 needs no warm worker (B3). Judging on release is a
  plain subprocess.
- The preview: **3.8 ms** per move (the loop: 150 ms).
- The tool, end to end on the real install (`c1_lab.py build`): Check 14.2 s, first time, which includes making the
  draft (1.6 s: one read and one write per file, the hash from the bytes in hand; `shutil.copy2` took 8.9 s). Accept
  10.6 s. Reading the island for the preview: 0.6 s for all 94 blocks; a canopy outline 1.4 s cold, 0.2 s warm.

## Found on the way

- **A test wrote into the live install.** `config.find_game_path` trusts an explicit path only when it exists and
  otherwise auto-detects the real game. A test whose temp game folder was not made yet deployed two stub meshes into
  `<install>/Src`, which the launcher would have activated. Caught within the run, moved out of the install, and
  both forest test files now close every fall-through (an autouse fixture, proved by a test that a missing path
  raises) and make the folder first.
- **PySide's `findData` does not match tuple item data reliably.** The donor combo holds the `--donor` spelling
  (`"13,15"`).
- **`isVisible()` is false for every child of an unshown window.** The tab asks `isHidden()` (was the tool put away?).
- **Three tool bugs**, each now fenced:
  - a click before the canopy had loaded fired its check into nothing and was never judged;
  - a typed spread of 1.33 would have run as `--spread 1.35` (the command now spells two decimals);
  - Copy command named the live folder before a draft existed (it now names the draft's path, always).
- **A draft holds disc 1's edits only.** The verbs' disc-4 mirror compares stock ground across discs, which needs the
  install's bundles; an absolute `--mod-folder` outside the install has none, so the mirror logs NOT RUN (the
  hand-typed command does the same). Promotion (C4) must run the mirror.
- **Not this rung's, seen in the snaps:** the Workspace's minimum width jumps from 1165 to 1434 px between two grabs
  of any World state, master's `atlas` → `atlas-site` included. The Place tab's `PlaceDoc` minimum grows 895 → 1164 once
  it polishes, and the stacked page takes the widest. At 1280 px that clips the Inspector pane. Also inherited: the
  app's spin-box QSS draws the up/down buttons without arrow glyphs (the Place and Trace tabs' spin boxes too).
