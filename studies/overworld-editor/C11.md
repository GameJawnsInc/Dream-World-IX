# C11: faster re-runs after an edit -- an island, a carry and a sink replay

**Status:** BUILT, 2026-10-24 (`c11_lab.py`, real bytes). Owner request: "Go on with faster re-runs after an edit:
give island, carry and sink steps a real read window so they replay instead of always running again."

## What changed

C9 puts the steps after an edited one back on top, each **replayed** from its record when no block it reads changed,
else composed again by `world-fuse` (10-40 s a step). The read window came from `recipe.row_cells`, which for every
table but the relief rows is the whole world, so an island, a carry or a sink after an edit always ran again.

`recipe.replay_window(step)` now gives each its measured window:

| table | read window |
|---|---|
| forest, mountain, hill | the row's reach (`row_cells`), as before |
| island | its footprint (the ring the mint draws for its seed) and the 8 blocks round each |
| transplant (one block or a unit) | its target rect, turned, and the ring round it |
| sink | the blocks it changed (its island, all of which it writes) and the ring round them |
| coast morph, river move | the whole world (not measured: they always run again) |

Columns wrap; the step's own cells are always in it. `row_cells`, the snapshot an Open recipe or a re-run takes
before it writes, is unchanged.

## How the windows were found: measured, then fenced

A probe ran each verb in-process on a fresh draft of the real FF9CustomMap-world, at a target its card calls lawful,
recording every file opened, every existence check (`os.stat`, `isfile`, `exists`), every listing and every glob
under the draft:

- **dry runs** read almost nothing (the island its own row listing, the sink its five blocks);
- **real runs** read the window above: the island its block and all 8 neighbours (column 23 too, for a block in
  column 0), the carry its rect and its neighbours, the unit (1x2) its rect and ring, the sink exactly its 5 blocks,
  both discs. Each also opens the ledger and lists the whole Disc1 tree; the listing is the disc-4 mirror's inventory,
  which keeps only the written cells.

**THE FENCE** (`test_on_real_bytes_an_island_a_carry_and_a_sink_read_only_their_window`, install-gated): the same
recorder, the same four real runs (island, carry, unit, sink) each on its own draft, and every block read must lie
inside `replay_window`. Taking the ring off the island's window, or the carry's, turns it red on the neighbours each
reads.

## The acceptance

**On real bytes** (`c11_lab.py build`: the real RecipeBar and the hill, island, carry and sink cards, real runners,
a draft of FF9CustomMap-world):
- H a hill at (64, -512) by the Landing Site, then, each well away from it, I an island at (32, -160) (seed 5),
  T the beach island (7,17) carried onto (3, 2), and S the sink of the island at (679, -387).
- H picked, opened with Edit, moved to (64, -504), accepted: **"The 3 steps after it are back on top (3 as they were,
  0 composed again on the new ground)."** No `world-fuse` job ran. Accept and put-back together took **7.7 s**, nearly
  all of it the hill's own Check-and-write; composing the four rows took **35.7 s**.
- **I1: the edited draft == `world-fuse` of the edited recipe composed onto a fresh draft, over 1,900 world files.**
  The replayed bytes are the bytes a re-run writes.

No game run: the replay restores the very bytes the cards accepted, and I1 holds them to the composed path, which every
earlier rung walked in game.

**Hermetic:** each table's window, the column-0 wrap included; and the two fixes below.

## Found on the way

- **THE MANIFEST DRIFT GATE refused an opened recipe's edit.** `world-fuse` refuses to compose over files its
  `world_manifest.json` recorded and that changed since (in a live folder, another session's work). In a draft they
  change by design: an edit undoes the steps and the card writes the moved shape. So after Open recipe (every row a
  `world-fuse` job, every file recorded), editing any step refused its own put-back ("exit code 2"). The editor's
  `world-fuse` jobs now pass `--allow-overwrite`, which waives that gate only; the ownership refusal at the write seam
  (another session's bytes) still stands. Fenced: `test_an_opened_recipe_can_be_edited_...` (red before).
- **An Edit clicked right after an Accept raced a reader.** The card reads the island again on a worker thread after
  an Accept; Windows refuses to delete a file another thread holds open, so `begin_edit`'s undo raised
  `PermissionError` half way and left the draft half undone (it rolled back only on a refusal). The undo now waits
  for the reader (`draft._retry`, up to 3 s), and `begin_edit` rolls back on a disk error too. Fenced on Windows:
  `test_an_undo_waits_for_a_reader_that_holds_a_file_open` (the same PermissionError without the wait).
- The carry's ring did not wrap: a carry onto column 0 read its neighbours in columns 0-1 only, never column 23
  (the island's did). The window is a superset either way; the carry's own seam behaviour is not this rung's.

## Not here

Read windows for the coast morph and the river move (they still always run again). A narrower `row_cells` for
islands, carries and sinks, so a re-run snapshots less than the whole map.
