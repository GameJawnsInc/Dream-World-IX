# C14: the carry at column 0 -- does it join wrongly across the wrap?

**Status:** ANSWERED + FIXED, 2026-10-24. Owner request: "Go on with the carry at column 0: find out whether a carry
there joins wrongly with column 23 across the wrap, and fix it if it does." C11's read probe had seen a carry onto
column 0 read its neighbours in columns 0-1 only, never column 23, where an island read all three.

## The answer

**The carry's own bytes never read the target's neighbours, on either side.** Its geometry comes from the donor
block (and the donor's own neighbours, for its strips); its stitch, weld and T-junction gates judge the donor's welds
and the carried block's frame. So there is no east/west asymmetry in what it writes, and nothing to join wrongly in
the carried bytes.

**One gate does read the target's ring: the orphan-decal census** (`orphangate`), which checks every transition
tile the carry brings for the context that justifies it, the tiles round it included. Its ring was CLIPPED to the
24x20 grid instead of wrapped: at column 0 the whole west ring fell away (and at column 23 the east). So the census
judged a west-edge tile with no context:
- by default it only warns, so a lawful tile there could read as an orphan;
- with `--redress-orphans` (opt-in on the CLI; the editor never passes it) it REWROTE the lawful tile. Measured on
  the hermetic repro, old code: ring `[]`, 1 tile redressed, its UVs changed; new code: ring `[[23, 0]]`, nothing
  redressed.

## The fix

`orphangate._ring_blocks` wraps columns and clips rows: a ring block keeps the column it has in the region's frame
(-1 west of column 0, 24 east of column 23), so its triangles land beside the region in world x, and
`default_context_provider` reads it at its label (column 23, column 0). The gate reports the ring by label.

## The acceptance

**Real bytes** (`world-transplant` of the beach island (7,17) onto (0, 3), where (23, 4) is held in
FF9CustomMap-world; old code = master, new = this branch; each run on its own fresh draft):

| run | ring the census read | orphans | redressed | world files, old vs new |
|---|---|---|---|---|
| plain (as the editor runs it) | old `[0,4] [1,2] [1,3]`; new adds `[23,4]` | 0 | 0 | identical over 1,871 |
| `--redress-orphans` | the same | 0 | 0 | identical over 1,871 |

So no carry the editor has made changes, and this one finds no orphan either way; (23, 2) and (23, 3) are open
ocean, with no terrain to read. No game run: the written bytes are unchanged.

**Hermetic** (`tests/test_world_orphangate.py`): the ring wraps columns and clips rows (column 0, column 23, a
region on both sides of the seam); a west-edge fringe tile whose grass partner is a deployed column-23 override is
cleared (not flagged, not redressed), and the mirror at column 23 reads column 0. Clipping the ring again turns it
red.
