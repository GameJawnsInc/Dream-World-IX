# C15: the north-south edge -- does anything placeable cross it?

**Status:** ANSWERED, 2026-10-24: nothing placeable crosses it, so no x-seam-style rung for z; one read fixed. Owner
request: "continue" (the next item: "the north-south edge -- whether anything you can place wraps that way at all").

## The engine wraps both ways

`WMWorld.Wrap` shifts every block left/right (`ShiftRightAllBlocks` / `ShiftLeftAllBlocks`) and up/down
(`ShiftUpAllBlocks` / `ShiftDownAllBlocks`); positions fold by 1536 in x and 1280 in z. So the world is a full torus:
row 19's south edge meets row 0's north edge in game, as column 23 meets column 0.

The kit treats rows as an edge ON PURPOSE (`mesh.wrap_block_col`: "z also wraps engine-side, but edged-z is kit
policy -- the row-bounds refusal (the dunes incident) stays"): `world-island` refuses a footprint past row 0 or 19,
and the relief verbs' read windows and the replay windows stop at the rows.

## Does any land meet across it? No

Every column's effective Terrain (the first folder of the stack that holds the block, else stock), land being
y > 0.3, measured from the row edge:

- stock ships no prefab at all in row 19 (open ocean); the kit's deploys there (columns 0-4, 6-8, 12, 18-20, 22)
  stop 4.5-61u short of the south edge;
- row 0's land (stock columns 0, 8-10; deployed 3, 20-22) starts 4.8-60u inside the north edge;
- **the narrowest water across the edge, diagonals included, is 23.6u** (column 1 of row 19 to column 0 of row 0).

A forest, mountain or hill needs grass under its whole rim, so none can straddle that water; an island cannot be
minted across it; the sink, the carry, the morph and the river all land inside one row band. So the clamped read
windows lose nothing today, and building a seam frame for z (C10's work for x) would build for a case that does not
occur.

## The one read that should wrap: the orphan census's ring

C14 made the orphan-decal census read its context ring across the x seam, but kept rows clipped, and wrote "rows stop
at the map's edge" into its docstring and test. That was wrong about the engine. The ring now wraps both axes (row -1
north of row 0 reads row 19, row 20 south of row 19 reads row 0), keyed beside the region and read at its label. It is
a READ of context; no write crosses the row edge, so the kit's policy stands.

## If this changes

The answer rests on the water gap, which is a property of the folder: a mint that brings land to a row edge on both
sides of it would make the clamped relief windows matter. The island mint's row refusal keeps a footprint off the edge
itself, not off its last 23u, so recheck the gap (the measurement is in this file's history) before building on it.
