## 0. The one-paragraph answer

The title screen is **not a `.eb` field and not data** — it is `TitleUI : UIScene`
(`Global/TitleUI.cs`, compiled into Assembly-CSharp.dll), running on NGUI GameObjects that live in
the *bootstrap* Unity scenes, loaded by build index outside every moddable path. **But Memoria's
authors already built a DLL-free skin surface for almost all of it**: the background, logo, menu
button art, attract slideshow, intro movie, boot logos, warning/credits text, and (with one ini
caveat) the title theme are all loose-file overridable from a mod folder — the installed Moguri mod
is live ground-truth proof for the bg/logo/FMV paths. What is **strictly DLL territory** is menu
*structure/flow* (add/reorder buttons, new actions) and inserting *new* pre-title sequencing — and
for the latter the recon found a purpose-shaped seam: the dead `GUIManager.SetFieldMap` bridge
scene, which could run a **custom field's `.eb` before the title** in ~2 s18-sized patch hunks.

## 1. Architecture — what the title screen actually is

**Boot scene chain** (verified from code + the `mainData` BuildSettings string table; the
MainMenu/Title split was a verifier catch — the original recon conflated them):

| # | BuildSettings scene | level file | Controller | Transition out |
|---|---|---|---|---|
| 0 | BundleSceneSelector | level0 | `BundleSceneSelector.cs` (Steam init) | `LoadLevel("SplashScreen")` :49 |
| 1 | SplashScreen | level1 | `SplashScreen.cs` (Square splash) | `LoadLevel("Bundle")` :18 |
| 2 | Bundle | level2 | `BundleScene.cs` (`GameInitializer.Initial`, bundle load) | `ReplaceNow("MainMenu")` :183/:259 |
| 4 | MainMenu | level4 | **`GUIManager.cs` — a transient bridge**, NOT the title | `LateUpdate` -> `Replace("Title")` :27 |
| 6 | Title | level6 | `TitleUI` via `UIManager` (`loadedLevelName=="Title"` -> `UIState.Title`, UIManager.cs:260/380) | New Game/Continue -> `Replace("FieldMap"/"WorldMap")` |
| 7 | FieldMap | level7 | `HonoluluFieldMain` reads `fldMapNo` -> runs the field's `.eb` | — |

Non-obvious structural facts (all byte-verified with UnityPy):

- **The title UI GameObjects do NOT live in Title.unity.** `level6` (Title.unity) is a near-empty
  4-GameObject FieldMap stub (`FieldMap Root`/`FieldMap Camera`/`FieldMain`/`BG Camera`). The real
  hierarchy — `Menu Panel` -> Background(0)/Logo(1)/`Menu Group Panel`(2)/Language(3)/Staff(4)/
  Movie(6)/Blackjack(7)/… — lives in **level1** (SplashScreen.unity, `Menu Panel` pathid 3826,
  `Menu Group Panel` pathid 2156) and is duplicated in **level2** (Bundle.unity).
- `Menu Group Panel` has **exactly 4 children in order**: Continue, New Game, Load Game, Cloud —
  matching the compiled `GetChild(0..3)` binding (TitleUI.cs:1387-1390).
- **Scene loads bypass Memoria entirely**: `Application.LoadLevel(name)` resolves via BuildSettings
  build index into the game's own `x64\FF9_Data\levelN`. AssetManager has no scene hook, and its
  loose-override surface covers only 5 typed named assets (TextAsset, Texture/Texture2D/Sprite/
  UIAtlas, AnimationClip — AssetManager.cs:24). **No mod folder can replace a scene**; Moguri ships
  zero level/.assets files (verified).
- `TitleUI`/`UIManager` MonoScripts sit in `sharedassets0.assets` (Assembly-CSharp.dll, pathids
  307/407) — the menu logic is engine code, same territory as our debug-menu patches.
- New Game (the already-proven seam): `OnNewGameButtonClick` :957 -> `FF9StateSystem.
  ReInitStateSystem()` :965 (-> `EventEngine.NewGame()`: wipes `gEventGlobal`, `fldMapNo = 70`,
  `InitEvents` — EventEngine.Initialize.cs:40-53) -> `Replace("FieldMap")` :966. Continue:
  `OnContinueButtonClick` :927 -> autoload -> `ReplaceLoadMap()` (FieldMap or WorldMap by saved
  `mode`, EventEngine.Initialize.cs:63-68).

**Title-BGM gotchas (all three verified):**
1. FMV000.bytes is **video-only** (single Theora stream, no Vorbis — byte-probed), so swapping the
   movie does NOT change the theme; `music033` plays separately.
2. The loose **`.ogg` route is inert under the shipped ini**: with `[Audio] PriorityToOGG=0`,
   `SoundLoaderResources.cs:27-32` loads the `.akb` first and only falls to the ogg on null. OGG
   swap requires `PriorityToOGG=1`; the **`.akb.bytes` drop-in needs no ini change**.
3. FMV000 is the ONE movie special-cased to `MusicPlayer` (SoundLib.cs:24-27), so the title theme is
   gated by **MusicVolume, not MovieVolume** — and this install has `MusicVolume=0`: the title
   theme is currently *muted* regardless of any swap.

Also verified: `[Import] Enabled=0` on this install, so the active sound loader is
`SoundLoaderResources` (SoundLoaderProxy.cs:13-16), which is what makes gotcha 2 binding.
The `title_world_*` textures in resources.assets are **world-map continent nameplates**, not the
title screen — easy name trap (they're the `world.navimap` surface).

## 3. Layer 2 — menu text

- The main button labels are **pre-rendered sprites, not strings** ("New Game"/"Load Game" appear
  in NO text file on disk — grep-verified). Changing their wording = repaint `General Atlas.png`,
  or remap which sprite a button uses: each button's NGUI **UILocalize key's VALUE is a sprite
  name** (`TitleNewGame0404 = "title_menu_newgame"` — `StreamingAssets\Text\US\System.strings:663-671`).
- Real Localization strings (save-preview panel `SlotNo/FileNo/EmptyFile/CorruptFile/NoSaveData/
  Save|LoadSlotHelp`, language button `NameShort`) live in `Text\<LANG>\System.strings` — active
  because this install sets `[Import] Text=1`; load order is embedded `Localization.txt` ->
  `Data\Text\LocalizationPatch.txt` (per-mod CSV, overwrites) -> `System.strings` (wins when
  Text=1) (LanguageMap.cs:55-63).
- `TextPatch.txt >INTERFACE` can rewrite any non-dialog UILabel (keyed on UILocalize key / label
  name / scene — TextPatcher.cs:215-228) but **cannot** touch the UISprite buttons. DictionaryPatch
  and `>DATABASE` are the separate FF9TextTool mesID namespace — they never reach any of this.
- **Latent engine bug** (verifier catch): `LanguageMap.LoadExternalText` uses `return`, not
  `continue`, when one language's `System.strings` is missing (LanguageMap.cs:219) — a partial
  per-language override silently aborts the remaining languages. Ship all 7 or none.

## 4. Layer 3 — a custom pre-title cinematic

Three rungs, cheap -> expensive:

1. **Replace the content of what already plays — DLL-free today.** Replacement intro movie =
   `<mod>\StreamingAssets\ma\FMV000.bytes`; replacement boot logo = ride the `logo_sst` sprite
   slot (loose PNG). Which movie plays is a hardcoded `"FMV000"` literal (TitleUI.cs:1842, inside
   `onLogoFinish`); the only data-driven movie list is the post-title gallery (`MovieFiles[]`
   :135-177, FMV001+).
2. **Add sequencing (extra logo, extra pre-FMV) — one s18-sized DLL hunk.** Extra FMV: chain a
   second `LoadMovie` in `onLogoFinish` (:1833-1846) with a finish callback; the new movie itself is
   a loose `ma\` file. Third logo: extend the `logoIndex` chain (:1817-1825/:1830/:1741-1752).
3. **A fully scripted pre-title FIELD (`.eb` cinematic before the title) — the headline seam,
   ~2 s18-sized hunks.** The MainMenu bridge `GUIManager` is purpose-shaped for it:
   - It already carries a **dead** `SetFieldMap(short no, int sc, int id)` helper (GUIManager.cs:
     54-59) — dead because `eBin` is only constructed in `InitEvents` (EventEngine.Initialize.cs:28),
     so it NPEs at MainMenu time. Grep-verified: nothing calls it.
   - **Hunk 1 (redirect):** in `GUIManager.LateUpdate`, instead of `Replace("Title")`: run
     `FF9StateSystem.ReInitStateSystem()` (the New-Game template — wipes gEventGlobal, sets
     `fldMapNo=70`, InitEvents), then override `fldMapNo = <intro field id>`, then
     `Replace("FieldMap")`. `HonoluluFieldMain.HonoAwake` consumes exactly those values.
   - **Hunk 2 (hand-back):** a field `.eb` has NO path to `Replace("Title")` (`Field(N)` ->
     `ReplaceLoadMap` -> FieldMap/WorldMap only). Intercept a reserved sentinel `Field()` id in
     `ReplaceLoadMap` -> `Replace("Title")`, or poll a reserved GLOB flag in
     `FieldMap.HonoLateUpdate` (the s18 seam). Note the live engine has 6 return-to-title callers
     (5 stock + our `NetSyncState.cs:147`).
   - The GUIManager path is **unaffected by SkipIntros** (all three gates are TitleUI-only), and
     returning to Title re-runs `PlaySplashScreen` — clean under SkipIntros=3, replays logos at 0
     (`SplashScreenEnabled` :116/:1266).
   - Open question before building: can a camera-only `.eb` run on the fresh ReInitStateSystem
     state, or does HonoluluFieldMain assume a player actor? (Field 70 works because NewGame seeds
     the opening party.)

**SkipIntros ladder** (Memoria.ini `[Graphics]`, default 0; **this install = 3**), code-verified —
the ini comment is subtly off: `==1` skips the two logos but *keeps* FMV000 (:1854); `>0` on
Splash/Logo is a *full* skip — no logos, no FMV000 (:1861); `>2` also stops the idle attract loop
(:1276). At 3, any title-scene-inserted intro is suppressed — another reason the GUIManager seam
(upstream of TitleUI) is the right insertion point.

## 5. Layer 4 — title menu mechanics: strictly DLL (verdict, high confidence)

- Buttons are bound by **compiled child index** (`GetChild(0..3)`, :1387-1390) and dispatched by
  **GameObject identity** in `OnKeyConfirm` (:391-448, per-`ButtonGroupState.ActiveGroup` else-if
  chains). Existence/order/nav links are baked scene data; visibility/dim is code
  (`SetActive`, `UISprite.color` :1097/:1105/:1114-1135).
- The scene holding the hierarchy is loaded by build index and **cannot be replaced by a mod
  folder** (§1). A 5th menu item therefore means: runtime GameObject creation under
  `Menu Group Panel` + a new field + `UIEventListener` onClick + ButtonGroupState nav wiring + an
  `OnKeyConfirm` branch + handler — an engine patch in exactly our debug-menu house style.
- **No community precedent exists** for an FF9 title-menu re-flow (web sweep: Moguri = art,
  MoguriVideo = FMV, launcher themes = the launcher app; nothing restructures the menu). We'd be
  first. (Negative claim — medium confidence by nature.)
- The one unpinned detail: which GameObject hosts the TitleUI MonoBehaviour (this build strips
  MonoBehaviour typetrees; 12 of 8794 level1 MBs parse — candidate GO `Title` pathid 3211, but
  level1 has TWO GOs named `Title`).

## 8. Verification ledger — what adversarial review changed

19/20 agents completed; 63 claims verified: 60 CONFIRMED, 2 REFUTED, 1 UNVERIFIABLE (stub). The
refutations were load-bearing:

- **BOOT-1/BOOT-2 REFUTED:** the original boot-flow lens conflated the `MainMenu` scene with the
  title. Ground truth: MainMenu (index 4) is the **GUIManager bridge**; Title (index 6) is TitleUI.
  The corrected model is what surfaced GUIManager + its dead `SetFieldMap` — the best seam found.
- **Scope corrections:** the `StreamingAssets\UI\Sprites\US\<name>.png` loose override applies to
  exactly ONE sprite (MenuPanel child 0), not "any sprite" (TitleUI.cs:287-296, a `// TEMP` block —
  prefer the EmbeddedAsset hooks); level files run level0..level27 on disk vs 29 BuildSettings
  scenes; Title.unity's 4 GameObjects are FieldMap objects, not a "trigger".
- **Two lens failures, both recovered:** `engine-title-code` died on structured-output retries and
  `prior-art` emitted stub data ("test claim") — the critic caught the stub and dispatched a real,
  verified replacement; TitleUI internals were fully covered by the other lenses + the Layer-4 gap
  agent.
